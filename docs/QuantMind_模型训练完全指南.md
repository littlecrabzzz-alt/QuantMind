# 模型训练操作指南

用途：配置可追溯训练、辨别任务完成与模型可用，并安全选择推理模型。本文不预设所有市场、模型或训练节点已具备合格数据。

## 开始前

1. 确认当前连接的后端与实际算力节点。本地 Mac 是唯一开发源；可选远端 GPU 只是执行任务的资源。
2. 在训练中心选择市场与训练数据源，查看实际日期范围、股票池和字段。特征目录由 `GET /api/v1/models/feature-catalog` 返回，数据源由 `training-sources` 返回，不沿用旧版固定特征数。
3. 明确标签周期与 `target_mode`。排名标签的模型输出是相对分数，不是可直接解释的收益率；标签使用未来收益，不能混入当时的输入特征。
4. 按时间划分训练、验证、测试集，预留标签窗口，确保预处理只在允许的数据上拟合。反复看测试集调参会使测试集变成开发集。

## 训练步骤

1. 先选一个计算资源可支持的简单基线，例如 LightGBM 或 Ridge，少量明确含义且覆盖充分的特征。模型是否可选以当前页面与后端校验为准。
2. 固定股票池、训练/验证/测试日期、预测周期、预处理和随机种子；记录数据版本。缺列、缺日期或样本不足应先处理数据，不用默认值掩盖。
3. 提交后保存 `run_id`，查看任务状态、日志与错误。切页后可恢复活跃任务；取消走任务取消入口，不直接杀整个后端。
4. 完成后检查指标对应哪个区间、样本数、特征清单及产物。`training` 成功不等于注册/同步成功，继续检查 `model_registration` 的状态与错误。
5. 模型达到可用状态后，在模型管理中设为默认，或在策略中单独绑定。一次切换只改变明确的使用方，不为了排错重置所有用户模型。

## 模型与资源选择

- 树模型适合作为表格因子基线；线性模型便于检查特征增量。不同模型的优劣要在同一数据与成本口径下比较。
- GRU/LSTM/TCN/Transformer 等时序模型需要正确的序列窗口、足够历史和匹配依赖；GPU 可加速但不保证效果更好。
- CatBoost 是否正确处理行业类别取决于实际数据类型与训练实现，不能仅靠勾选某个字段保证。
- Optuna 或集成会扩大搜索与选择偏差；保存所有候选及预算，不能只记录最优结果。先验证单模型与数据，再做集成。
- 不承诺固定训练耗时、IC 阈值或集成提升比例。CPU/GPU 是否可用取决于镜像、驱动、节点配置及模型实现。

## 评价与使用边界

Rank IC 衡量预测排序与未来收益排序的一致性；ICIR 反映其跨日期稳定性。指标必须附区间、样本量与计算口径，不能用某个固定数值代替准入。

在相同股票池、交易时点、费用和成交约束下比较样本外收益、回撤、换手、暴露及未成交情况。评估完成前保持候选用途，不因页面可激活就认定适合实盘。

多市场选择不等于数据已经可用。CN/HK/US/期货等分别核实价格口径、交易日历、可得时点、标签和目标引擎支持范围。

## 排错与接口

| 问题 | 先检查 |
| --- | --- |
| 可选字段为空/时间段不可选 | 数据源挂载、数据目录与实际日期覆盖 |
| 节点无法执行 | 节点的执行模式、依赖、网络与数据位置；不要把整套系统重新部署到训练节点 |
| 训练成功但模型不可用 | 注册状态、同步错误、权重/元数据/特征维度 |
| 切换后仍是旧结果 | 显式模型 ID、策略绑定、用户默认及该次结果中的实际生效模型 |

主接口位于 `backend/services/api/routers/model_training.py`：`POST /api/v1/models/run-training`、`GET /api/v1/models/training-runs/{run_id}`、`POST /api/v1/models/training-runs/{run_id}/cancel`。用户身份由认证上下文提供，不在文档中伪造其他用户请求。

完整选择规则与产物合同见 [推理与模型选择](模型推理服务设计与链路文档.md)；策略侧见 [模板编写](QuantMind策略编写手册_v2.md)。
