# 研究案例登记与分阶段验证

用 RRG 行业轮动作为首个案例，把研究资料与可复查的执行记录连接起来。标准流程为：**登记来源 → 冻结方案 → 数据准入 → 实验 → 独立复核与结论回填**。每一步保留证据，数据不足时记录缺口，不生成或推测策略收益。

当前实现入口是 `scripts/research_case.py`，仅提供 `register`、`check`、`status`、`verify`。这四个操作完成来源登记、方案留档、数据检查与产物完整性核验；没有执行 RRG 回测，也没有注册平台模型或触发交易。

当前自动检查的范围是文件可用性、字段和部分字段取值。历史时点正确性、完整行业覆盖、价格有效性及执行语义仍需后续核验，因此即使所有结构检查通过，本版本也只会进入 `awaiting_data_review`，不会自动进入实验或标记方法已验证。

## 1. 登记来源与研究问题

来源继续复用 `scripts/research_watch.py` 的采集结果：SQLite 的 `entries` / `versions` 提供来源 key 与内容指纹，`digest_state.json` 提供既有阅读评审记录。RRG 案例关联已归档的 QuantsPlaybook 提交与本地研究笔记，不把“已经评审”解释为“已经复现”。

案例使用独立身份，记录研究问题、来源版本、证据阶段、实验范围和失败条件。同一篇资料的后续修订仍需显式确认采用的版本，不能自动替换已登记案例的输入。

现有 `/research/pool` 是按股票代码组织的个股研究池；本流程先使用文件案例，不将 RRG 方法写成一只股票。

## 2. 冻结方案

默认研究合同为 `config/rrg_sector_rotation.json`，默认案例目录为 `data/research_cases/rrg-sector-rotation`。登记后保存的合同是该案例的实验边界。修改合同后必须使用新的案例目录，保留旧版本及其检查记录。

合同应在查看实验结果前明确：行业分类与范围、信号公式和参数、调仓与成交时点、比较组、成本、数据要求、验收及否决条件。RRG 首先验证行业信号，再考虑扩散度和 ETF 映射；阶段之间分别验收。

```bash
# 使用默认合同与案例目录登记。
python3 scripts/research_case.py register

# 检查本地数据，生成本次检查的独立记录。
python3 scripts/research_case.py check

# 查看案例进度、数据缺口与下一步。
python3 scripts/research_case.py status

# 核验已登记资料及检查产物的完整性。
python3 scripts/research_case.py verify
```

另建案例时，使用 `--config` 指定合同、`--output` 指定新目录；后续操作继续指向同一目录。例如：

```bash
python3 scripts/research_case.py register \
  --config config/rrg_sector_rotation.json \
  --output data/research_cases/rrg-sector-rotation-next
```

`check` 完成检查但数据尚未准入时返回退出码 `2`，仍会留下报告；这与运行异常不同。`status` 和 `verify` 读取并核验既有案例的冻结状态，传入配置也须与冻结合同一致，不应用新合同。自动脚本应同时读取状态和退出码，不能只看进程是否正常完成。

方案和源码指纹可以说明检查采用了什么版本，不能证明原始数据在历史时点已经可得。真正执行实验前仍需冻结实际输入数据及运行环境。

## 3. 数据准入

数据检查分别判断以下三层，保留每个结论的证据、缺失项和后续动作。发现文件或字段不等于满足研究要求；缺少历史时间或来源依据时不能判为通过。

| 层次 | 进入实验前需要证明什么 |
| --- | --- |
| 行业信号 | 分类版本与完整行业名单确定；行业指数及基准日历对齐、价格有效、代码与日期组合唯一；覆盖预热和实验区间。 |
| 行业扩散度 | 成分股归属在各历史时点可确定，个股价格可比且覆盖回看期；市值加权版本另需当期可得市值。 |
| ETF 执行 | 历史产品池、上市退市及可交易状态可确定；持仓以公告时点约束可得性；成交开盘价与估值收盘价复权口径一致。 |

参数 `220 / 60 / 20` 若采用两层完整滚动窗口，首个有效 RS-Momentum 需要 319 个价格观测，即 318 个预热间隔。预热充分也不代表后续实验区间已经覆盖。

ETF 持仓的报告期不等于公告日期。名称映射、当前成分股和当前 ETF 持仓只能支持当期观察，不能直接用于历史轮动复现。持仓披露不完整时还需保留未解释暴露，不能把已披露部分任意放大为完整组合。

### 本轮本地观察（2026-09-08）

以下是本轮检查准备阶段观察，详细数量、字段、路径与最终判定以生成的检查报告为准：

- 本地 `index_daily` 根目录有 48 个指数文件，其中识别到 7 个中证行业指数；未找到预期的完整中信或申万行业指数集合，不能以总文件数证明行业覆盖完整。
- `sector_members` 没有历史日期字段；观察到的 48 个一级名称也不是所需中信行业集合，不能直接用作历史行业成分。
- `etf_components` 没有日期字段，无法据此证明持仓在调仓时已经公开。
- ETF PCF 的 `tradingDay` 观察值全部为空，不能作为可用的历史时点证据；ETF 复权及成交价格口径仍需核对。
- 首次正式检查中，ETF 行情根文件只覆盖 2026-08-28 至 2026-09-03 的 5 个交易日；结构字段齐全也不足以支持合同中的历史比较区间。检查范围由合同中的文件匹配规则确定，不代表已穷尽其他目录或其他格式的数据。

这些缺口会阻止依赖它们的实验阶段。本轮可以完成登记与检查流程，但不产生 RRG 收益、超额收益或策略有效性的结论。

## 4. 独立检查记录与状态回填

案例目录中的 `case.json` 保存来源与登记清单，`registration/` 保存冻结合同、来源记录、评审记录和研究笔记副本，`state.json` 保存执行状态。每次 `check` 在 `checks/` 下创建独立目录，保留 `inputs.json`、`report.json`、`README.md`、运行时信息、检查代码副本及产物清单，不覆盖既有检查。后续补齐数据后重新运行检查，保留前次不足及本次变化。

| 状态字段 | 当前实现的含义 |
| --- | --- |
| `workflow_stage` | 登记后为 `registered`；结构检查发现缺口为 `blocked_data`；没有结构缺口但语义尚未验证为 `awaiting_data_review`。 |
| `learning_status` | 保持 `candidate_experiment`。 |
| `evidence_level` | 登记后为 `source_review`；产生数据检查后为 `local_data_audit`。 |
| `readiness` | 分别记录 `signal_layer`、`breadth_layer`、`etf_execution`，取值为 `blocked` 或 `needs_review`；前置层受阻时后续层也受阻。 |
| 单项 `status` | `passed` 仅表示该项结构检查通过；数据缺口为 `blocked`；尚未完成的语义核验为 `unknown`。 |
| `latest_check` | 最近完成并写入状态的检查目录；登记后尚未检查时为空。 |
| `completed_checks` | 已完成检查目录及各自的清单哈希，供逐次验证历史检查完整性。 |
| `local_reproduction` / `automatic_trading_authorized` | 当前均为 `false`。 |

检查过程发生异常时保留失败目录及错误记录，供后续诊断；不把半成品检查作为新的完成结果。数据缺口属于有结论的检查结果，仍会成为最新检查。

状态回填文件为 `data/research_watch/research_case_state.json`，供研究采集流程关联案例进度。原采集评审文件 `digest_state.json` 保持原样，来源的阅读、报告状态与案例的执行证据分开保存。

`status` 用于查看阶段、检查结果与待补数据；`verify` 用于核验保存的证据是否完整、一致。完整性核验通过不表示数据准入通过，也不表示方法已复现或存在投资价值。

## 5. 数据合格后的实验与复核

未来实验沿用 [冻结研究框架](frozen-research-workflow.md) 的输入快照、内容哈希、固定运行环境、独立运行目录及结果核对方式。当前 `frozen_research_worker.py` 是个股 LightGBM / TopK 实验，使用次交易日收盘成交；它没有实现本案例需要的 ETF 月末信号、次交易日开盘执行，不能直接换配置就称为适配完成。

执行前须补齐并验证与 RRG 对应的信号和执行接口，再冻结真实输入。先在同一数据和费用口径下比较等权、简单动量与 RRG；扩散度及 ETF 暴露优化按阶段增加，分别判断是否提供增量。

实验完成后独立核对实际日期、信号可得时点、成交、持仓、现金、费用与净值，再将产物位置、检验结果、局限和采用或暂缓决定回填案例。未通过准入、未跑通复现、开发区间比较与独立验证是不同阶段；报告文字必须与数值证据一致。
