# Strategy Lab 用户手册

用途：在策略实验室编写事件式 Python 脚本、检查回测结果并保存可继续研究的策略。Qlib 原生模板使用另一套接口，见 [模板编写](QuantMind策略编写手册_v2.md)。

## 第一次使用

1. 登录后进入侧栏“策略实验室”，从示例库选择一份代码。
2. 在 `setup(ctx)` 中明确股票池、起止日期与资金，确认目标后端已有相应行情。
3. 点击运行，查看进度与日志。回测失败先读错误摘要及原始错误，不默认同步全市场数据或重启服务。
4. 完成后检查净值、交易明细、持仓与 K 线买卖点；`reason` 可用于解释订单动机，但不是成交保证。

```python
def setup(ctx):
    ctx.universe = ["sh600036"]
    ctx.start = "2024-01-02"
    ctx.end = "2024-06-30"
    ctx.cash = 1_000_000


def on_bar(ctx, bar):
    if bar.symbol == "sh600036" and ctx.position(bar.symbol).qty == 0:
        ctx.buy(bar.symbol, weight=0.5, reason="initial allocation")
```

这是接口示例，不是投资推荐；运行需要对应日期数据。

## 编写与调试

- `ctx.history()` 读历史价格，`ctx.feature()` 读可用特征，`ctx.list_features()` 查看实际字段；不要硬编码旧版特征维数。
- `ctx.buy()`、`ctx.sell()`、`ctx.set_position()` 表达交易意图；实际成交仍受资金、持仓、费用和成交规则约束。
- `ctx.param()` 声明研究参数，`ctx.log()` 输出诊断；`ctx.plot_line()` / `ctx.plot_marker()` 提供图表标记。
- 不导入系统、网络、子进程模块，不使用 `open/eval/exec/__import__` 或双下划线对象绕过检查。
- AI 助手的“应用到编辑器”会替换代码；应用前审查改动，尤其检查标签泄漏、日期和交易时点。

只运行可信代码。当前 AST 检查和子进程超时不是完整的不可信代码隔离，具体边界见 [SDK 与接口合同](Strategy_Lab规范.md)。

## 如何解释四关检测

页面提供时间切分、分段走查、参数敏感度和蒙卡检测，评分只作为诊断线索，不是过拟合已排除或可上线的证书。

- 未声明可枚举参数时，参数关卡会以跳过结果给分；这不是完成了敏感度实验。
- 当前蒙卡实现打乱同一组日收益后比较累计收益；收益乘积对顺序不变，因此不能以其排名证明策略显著性。
- 同一测试区间被反复用于修改策略后，不再是独立样本外。应保留真正未参与选择的区间与成本一致的对照。

## 保存、翻译与扫描

“转模板”将 Lab 脚本转换并保存为后续策略模板，不会代替独立回测、资金授权或券商配置。转换后重新核对股票池、日期、费用及下单语义。

“加入每日扫描”登记脚本；自动执行还需要实际运行的 Celery beat/worker 和扫描开关。Mac 隔离环境默认不启用调度器，登记成功不代表每天会执行。“立即扫描”会真实计算并写结果，不是只读状态查询。

## 留下复现依据

保存 `run_id`、脚本、参数、实际股票池、成本、模型/数据来源与结果。`script_sha` 只标识代码与参数；`data_snapshot_at` 若缺失不能补造，也不能单凭同一个哈希承诺重跑数值一致。

常见失败依次检查：语法/AST 拒绝 → 配置字段 → 数据范围/股票代码 → 原始运行日志 → 超时与资源。接口字段和维护边界见 [规范](Strategy_Lab规范.md)。
