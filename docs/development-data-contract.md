# 开发、业务数据与固定研究输入

Mac 是唯一开发源。远端开发与跨端 handoff 已退役；这不代表远端业务服务、数据库、备份或市场接收端已经迁回 Mac。操作任何数据前，先核对实际节点、容器挂载、数据库连接和任务状态，不能用代码目录位置推断数据归属。

## 写入边界

- 市场供应商采集写入独立源目录，按[本地市场数据源](local-market-source.md)交付已校验文件；不传 PostgreSQL、Redis 队列或研究结果。
- 现有云端业务库由其业务服务维护。本地 `.local-dev` 是独立沙盒，不是业务主库备份的可写别名；禁止整库回灌、双向同步运行数据，或启动旧库作自动兜底。
- 一个数据集只有一个发布者。暂存、自然键去重和完整校验结束后才原子发布；读者不读半成品，不改已发布 release 或运行中输入。
- 重试复用稳定自然键/业务请求 ID，通过唯一约束与 upsert 保持幂等；同键的不同观测或供应商修订不能静默丢弃。数据库 schema 变更使用版本化迁移。
- 密钥、节点配置、锁、租约、临时文件及队列留在各自环境，不写文档或 Git；不以 Syncthing 同步业务数据。源码同步也不等于运行服务已发布。

## 本地沙盒

在 Mac 主工作树使用现有入口，不启动旧完整 Compose 栈：

```sh
bash scripts/local-dev.sh init
bash scripts/local-dev.sh start core
# 需要本地完整开发服务时，改用 start full
bash scripts/local-dev.sh stop
```

`init` 从已校验的 `logs/cloud-snapshots/latest` 创建 APFS 写时复制数据副本和独立卷；已有业务卷时拒绝覆盖。初始化失败保留副本/卷，不生成 READY。APFS 克隆共享底层块，不能把目录逻辑大小直接当成实际占用。

完整数据库基线由 `.local-dev/SNAPSHOT_ID` 标识；行情后续应用由 `.local-dev/QUANTDB_SYNC.json` 标识，两者不是同一进度。新快照或 CURRENT 不自动替换运行中实验输入。更新基线前保存需要的成果、确认任务空闲并按入口显式重建；没有自动合并两套数据库的路径。

`local-dev.sh` 检查 Mac、Docker Desktop 本地 socket、角色及操作锁，拒绝 `DOCKER_HOST` 覆盖；停止/切换会检查活动子任务。业务 beat 和实盘不是开发默认启动项。`stop` 仍可能恢复既有云端隧道；连接云端的页面操作会写真实业务数据，不能当作本地测试。重启容器不一定加载新环境或挂载，改变它们应在空闲窗口使用对应重建入口。

## 研究留痕与准入

正式研究记录任务 ID、固定输入 release/快照 ID、数据截止时间、文件校验、代码提交（含未提交补丁哈希）、参数、随机种子、依赖/镜像版本和输出校验。成果留在明确的本节点任务目录；不得让传输、缓存更新或代码回滚改变已有输入。

采集成功、固定版本发布、传输完成、PG/Qlib 派生完成、研究实际读取是五种不同证据。空响应、权限拒绝、部分源失败、历史覆盖和 PIT 缺口分别保留。最新日读取成功不能证明历史时点可得、复权收益正确或策略有效。

没有通用的按项目双向同步、整库合并或运行中任务迁移入口；不能把旧协作设计当成已上线能力。数据维护不启动训练、策略、虚拟盘或实盘。已有研究准入和验证集规则不因数据更新而放宽。

## 备份与服务维护

备份、磁盘保护和数据库故障恢复见[存储与服务恢复](storage-recovery-20261009.md)。回滚代码不回滚数据。远端发布前单独核对实际运行参数、镜像和挂载；保留私有配置差异，不以默认 Compose 覆盖现场。对外入口必须单独验收认证与 TLS，不能把页面登录或某次迁移成功当作公网安全证明。
