# 开发、业务数据与固定研究输入

Mac 是唯一开发与业务运行机器。Main 工作树用于开发，主业务运行代码使用 `~/Library/Application Support/QuantMind/primary-runtime-*` 中已核准的独立快照；修改 Main 不自动发布到主业务。运行入口及安装合同见[本地主业务运行](local-primary.md)。操作数据前核对本机实际容器、挂载、数据库连接和活动任务，不能用源码目录推断运行数据归属。

## 写入边界

- 市场供应商采集写入独立源目录，按[本地市场数据源](local-market-source.md)交付已校验文件；不传 PostgreSQL、Redis 队列或研究结果。
- 主业务库由 `quantmind-local` 栈维护，运行数据位于主运行快照的 `.local-primary/project` 及其独立命名卷。本地 `.local-dev` 是独立沙盒，不是业务主库的可写别名；禁止整库回灌、共享可写数据库目录或启动旧库作自动兜底。
- 一个数据集只有一个发布者。暂存、自然键去重和完整校验结束后才原子发布；读者不读半成品，不改已发布 release 或运行中输入。
- 重试复用稳定自然键/业务请求 ID，通过唯一约束与 upsert 保持幂等；同键的不同观测或供应商修订不能静默丢弃。数据库 schema 变更使用版本化迁移。
- 密钥、运行配置、锁、租约、临时文件及队列留在各自受控运行目录，不写文档或 Git，不以文件同步工具同步业务数据。代码提交不等于运行服务已发布。

## 本地沙盒

沙盒由 Main 工作树中的 `scripts/local-dev.sh` 管理，Compose 项目为 `quantmind-dev`，数据位于该工作树的 `.local-dev/project` 和独立卷。它与主业务栈都使用本机 8000，不能同时启动；两个入口均有互斥检查。查看已有沙盒状态：

```sh
bash scripts/local-dev.sh status
```

初始化只消费既存、已校验的完整基线，不会创建新的本地主业务备份；不应把它列为日常主业务操作或故障自动回退。初始化失败保留副本/卷，不生成 READY。APFS 克隆共享底层块，不能把目录逻辑大小直接当成实际占用。

完整数据库基线由 `.local-dev/SNAPSHOT_ID` 标识；行情后续应用由 `.local-dev/QUANTDB_SYNC.json` 标识，两者不是同一进度。新快照或 CURRENT 不自动替换运行中实验输入。更新基线前保存需要的成果、确认任务空闲并另行核准重建范围；没有自动合并两套数据库的路径。

`local-dev.sh` 检查 Mac、Docker Desktop 本地 socket、角色及操作锁，拒绝 `DOCKER_HOST` 覆盖；涉及切换的操作会检查活动子任务。业务 beat 和实盘不是开发默认启动项。本文不提供沙盒启动/停止切换流程；不能把旧模式切换当成主业务维护入口。重启容器不一定加载新环境或挂载，改变它们应在空闲窗口按对应栈的实际配置安排重建。

## 研究留痕与准入

正式研究记录任务 ID、固定输入 release/快照 ID、数据截止时间、文件校验、代码提交（含未提交补丁哈希）、参数、随机种子、依赖/镜像版本和输出校验。成果留在明确的本机任务目录；不得让缓存更新或代码回滚改变已有输入。

采集成功、固定版本发布、本地应用完成、PG/Qlib/H5 派生完成、研究实际读取是不同证据。空响应、权限拒绝、部分源失败、历史覆盖和 PIT 缺口分别保留。最新日读取成功不能证明历史时点可得、复权收益正确或策略有效。

没有通用的整库合并或运行中任务迁移入口。数据维护不启动训练、策略、虚拟盘或实盘。已有研究准入和验证集规则不因数据更新而放宽。

## 备份与服务维护

备份、磁盘保护和数据库故障恢复见[存储与服务恢复](storage-recovery-20261009.md)。回滚代码不回滚数据。主业务维护使用已安装主运行快照中的 `scripts/local-primary.sh`，先核对运行参数、镜像和挂载，保留私有配置差异，不以默认 Compose 覆盖运行实例。API 8000 与页面 3080 仅绑定本机回环；页面登录不代替权限边界验收。
