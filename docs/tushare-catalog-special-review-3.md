## 特殊边界与新增发现

### doc213：旧疫情引用失效

[大模型语料总览 doc142](https://tushare.pro/document/2?doc_id=142) 正文保留“全球新冠疫情数据”链接 [doc213](https://tushare.pro/document/2?doc_id=213)。当前公开页面 HTTP 200，但正文为 `404, 文档不存在！`。因此只能登记失效文档及原始标题/父链接；本轮无法由有效官方页面确认 API 名、最后更新时间、历史边界或权限，不能凭旧知识编写 HTTP 请求。

这也说明当前标题和旧正文可能属于不同更新时期；不能只用页面标题来解释其全部能力，亦不把旧链接从覆盖审查中消失处理。

### 因子库：供应商成品数据，独立权限

[doc486 `factor_list`](https://tushare.pro/document/2?doc_id=486) 明确因子库是独立付费权益；[doc490 `factor_value`](https://tushare.pro/document/2?doc_id=490) 提供 5000 积分以上试用说明。两者并非 `pro_bar` 式本地 SDK 合成，也不是现有原始行情的自动等价产物。10100 积分与已经购买的文本权限不能推定因子库全历史已授权。

doc485 宣称 202 个因子、历史起点 2010-01-04；因子列表会增长，各因子/标的的实际开始和空值需分别验证，不能把产品起点当每项历史完备证明。doc490 最大 6000 行，至少给 ts_code 或 factor_name；后续若获权，使用现有列表发现→标的/日期范围拆分模式即可，不能无参全库调用或把页面中示例因子全集化。

doc485 的资产类别写 Stock，而 doc486 的请求枚举当前股票值写 STK；应保留响应原文并依叶子契约形成请求，不把介绍中的词直接用于供应商参数。总览描述大部分截面处理在 [0,1]，doc490 示例却包含负数，因此不能给全部 factor_value 加“必须非负/必须 [0,1]”约束。该冲突仅为文档证据，需按因子定义验证。

### 自选组合：读取和修改必须区别对待

[doc474](https://tushare.pro/document/2?doc_id=474) 示例中的四个 API 均已有台账条目。`p_list/p_get` 读取账户当前组合，返回创建/更新时间不证明提供全部调仓历史；若未来需要本地保存，只能从实际观察形成版本，不能宣称能回填不存在的历史版本。

[doc445 `p_save`](https://tushare.pro/document/2?doc_id=445) 创建/修改组合，doc474 说明同名会覆盖旧成分；[doc447 `p_delete`](https://tushare.pro/document/2?doc_id=447) 删除账户组合。它们是用户状态修改操作，应明确 `operation=write/delete`、`auto_acquisition=false`。不应为了“尽量同步数据”或权限探针自动调用。每用户最多 200 组合是产品限制，不是分页上限；doc447 的 name 类型表为 int 而示例用字符串，需记契约差异，不能根据类型表自动转换或用真实删除验证。

这里没有交易指令接口，亦不能由组合保存推定有交易执行能力。本批只读文档，没有访问用户组合或改变上游状态。
