# 运行与部署

## 当前开发入口：本地 Mac

本地 Mac 是本项目唯一开发源；远端开发与双端 handoff 已退役。这不代表服务、数据库、数据集或交易执行端已迁到本机。修改前先确认目标实例，不能根据目录或旧文档推断运行位置。

本地隔离环境只通过仓库根目录的包装脚本操作：

```bash
bash scripts/local-dev.sh status
```

需要启动且已有初始化环境时：

```bash
bash scripts/local-dev.sh start core
```

- `core`：数据库、Redis、后端；`full`：再启用 worker、数据网关、RSS、QuantBot；`research`：增加研究 worker，需要研究快照。
- `.env.local` 是本机私有配置，不提交。运行数据在 `.local-dev/project/`，不是根目录 `data/`、`models/`、`db/`。
- `init` 只用于首次创建隔离环境：它要求 `logs/cloud-snapshots/latest/COMPLETE` 及完整备份，拒绝覆盖现有环境。缺备份时不要跳过检查或造一个 READY 文件。
- 包装脚本会检查本机 Docker Desktop、隔离角色、端口和隧道冲突。不要用裸 `docker compose up` 绕过它。
- 代码变更需要重新加载时使用 `restart-backend`；本地服务配置变更需要重新创建时使用 `recreate-backend`。切换前先检查正在运行的任务，不要把重启当默认排错动作。
- 本地 overlay 默认关闭实盘、通达信推送及自动同步；不要为复现旧部署说明而开启这些开关。

前端构建与连接配置见 [Electron 编译](Electron编译方案.md)。

## 可选 Linux 首次部署

以下是另建 Ubuntu 22.04/24.04 实例的安装入口，不是本地开发方式，也不是维护已有实例的快捷替代品。执行前检查脚本、安装目录、端口、网络暴露、磁盘和备份。

| 入口 | 用途与影响 |
| --- | --- |
| `deploy/deploy.sh` | 在线源码安装；会安装系统依赖、配置 Docker、同步代码、生成首次配置并启动服务；不包含业务数据 |
| `deploy/full-deploy.sh` | 从发布包导入镜像及可用的数据/模型/备份；需核实包来源、清单、版本与恢复目标，不保证包内数据适合当前业务 |
| `deploy/install-model-deps.sh` | 已明确需要 PyTorch 时重建依赖镜像；默认会重建并重启，`--refine` 只构建不重启；不是 Mac 包装脚本 |

新实例已审阅源码后可从仓库根目录执行 `sudo bash deploy/deploy.sh --ref <已审阅版本>`。不要把远程脚本直接管道交给 root，也不要在已有工作树使用 `--force` 覆盖本地修改。数据库恢复和 `QUANTMIND_REPLACE_*` 开关必须逐项确认，不可照抄默认完整部署流程。

首次运行前配置独立密码与密钥、限制数据库/缓存/内部服务端口，并核实实际认证方式。不要依赖文档中的历史默认账号。

## 已有实例维护

1. 确认实例所在主机、Compose 项目名、全部 `-f` overlay、env 文件、镜像版本及挂载；保留其现有启动入口。
2. 备份 PostgreSQL、Redis、模型、业务文件和相关持久卷，并确认恢复方法。源码 Git 历史不是业务备份。
3. 根据实际挂载判断改动生效方式：源码 bind mount 的代码重载与镜像内代码更新不同；依赖变化需要构建新镜像。只重启不能切换镜像或应用全部 Compose 配置变化。
4. 维护命令必须沿用该实例的完整 Compose 参数，仅操作目标服务；不要用裸 Compose、全量部署脚本或恢复离线包代替更新。
5. 更新后检查服务状态、日志、`/health`、登录、所需数据范围及业务任务；健康接口成功不证明训练、推理或交易链路可用。

不要执行 `down -v`、删除数据目录或重建业务库来处理普通启动错误。

Linux 基础 Compose 通常将根目录 `data/` 映射到 `/data`、`models/` 映射到 `/app/models`；本地 overlay 使用 `.local-dev/project/`。以目标实例实际挂载为准。

- [QuantDB 数据包导入](QuantDB_数据包解压指南.md)：只处理数据文件，不恢复业务数据库。
- [训练操作](QuantMind_模型训练完全指南.md)、[推理与模型选择合同](模型推理服务设计与链路文档.md)。
- [FinBERT 依赖与启用](FinBERT%20中文金融情感模型.md)。
- [大 QMT 执行端](大QMT真单镜像_部署与上线手册.md)、[可选通达信桥](integrations/tdx-bridge.md)：交易端独立部署，禁止从旧机器配置推断当前可用性。
- 可选 GPU worker 的脚本在 `deploy/autodl/`；远端算力是任务执行资源，不是第二个开发源。先核实训练编排器的执行模式与目标数据，再申请资源或启动训练。
