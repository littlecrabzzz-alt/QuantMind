# 本地 Mac 运行与部署

QuantMind 只在本地 Mac 单机运行。主业务入口是 `scripts/local-primary.sh`，使用本机 Docker Desktop；不要用裸 `docker compose up` 绕过包装脚本的状态、数据和端口检查。

## Main 开发源码与 Library 运行快照

- Main 工作树是开发源码，保留在原有位置；修改 Main 不会自动更新正在运行的业务版本。
- 主业务使用 `~/Library/Application Support/QuantMind/primary-runtime-<approved-version>/` 下已核准的代码与部署快照。日常操作必须调用这份快照中的脚本，不能误用 Main 中的脚本启动另一套运行目录。
- 主业务 Compose 项目为 `quantmind-local`，运行数据位于该快照的 `.local-primary/project/`，数据库和 Redis 使用该项目的独立持久卷。不要将根目录 `data/`、`models/` 或沙盒数据当成主业务数据。
- `.env.local`、`config/runtime.env` 是私有配置；安装快照时按原字节复制并设为 `0600`，不提交凭据。输出归档由显式指定的 Library artifact-root 管理，不复制到开发源码中。

## 已准备主业务实例的日常入口

先把变量设置为当前已核准的实际快照目录：

```bash
QM_RUNTIME="$HOME/Library/Application Support/QuantMind/primary-runtime-<approved-version>"
bash "$QM_RUNTIME/scripts/local-primary.sh" status
```

按需选择命令，不要把停止、启动作为默认排错步骤：

| 命令 | 作用与前提 |
| --- | --- |
| `bash "$QM_RUNTIME/scripts/local-primary.sh" start` | 启动已准备且已有恢复验证的主业务实例；要求 `.local-primary/READY`、`AUTHORITY.json` 及验证记录，拒绝与运行中的沙盒并存 |
| `bash "$QM_RUNTIME/scripts/local-primary.sh" stop` | 停止主业务栈，保留持久卷；执行前先确认任务和数据写入状态 |
| `bash "$QM_RUNTIME/scripts/local-primary.sh" status` | 查看服务状态、实例记录和本机 8000 监听归属；不代表全部业务链路已经验收 |
| `bash "$QM_RUNTIME/scripts/local-primary.sh" install-autostart` | 安装当前快照的登录启动入口；只在明确需要时操作 |
| `bash "$QM_RUNTIME/scripts/local-primary.sh" uninstall-autostart` | 卸载该登录启动入口，不删除业务数据 |

API 仅绑定 `127.0.0.1:8000`，Web 为 `127.0.0.1:3080`；数据库、Redis 和内部服务不发布宿主端口。主业务 `start` 不会因已有研究设置自动启动研究 worker 或 Agent，也不授权新研究、训练或采集。实盘与通达信推送保持关闭。

## 安装新的受管代码快照

在 Main 工作树根目录执行文件安装入口；目标运行目录必须不存在，artifact-root 必须是已存在且与运行目录不重叠的 Library 受管真实目录：

```bash
bash scripts/local-primary.sh install-runtime \
  "$HOME/Library/Application Support/QuantMind/primary-runtime-<approved-version>" \
  "$HOME/Library/Application Support/QuantMind/primary-artifacts-20261016"
```

安装器使用 Git tracked/staged 名单对应的当前工作树字节，按白名单复制源码、部署配置和已有前端构建资源，写 `MAIN_CODE_MANIFEST.json`；不复制运行数据、依赖目录或模型二进制，不重新构建前端。它是纯文件安装，不启动 Docker、不安装登录启动、不恢复业务库，也不创建 `READY`。安装成功不能当作新实例已可启动或恢复已完成。

本指南只覆盖当前已准备实例和代码快照安装；业务数据恢复或重新建立实例须作为独立维护任务，先明确可用工具、输入和验证要求，不伪造状态文件放行。完整快照合同见 [Mac 单机运行](local-primary.md)。

## 独立开发与研究沙盒

`scripts/local-dev.sh` 仅管理 Main 下已有的隔离沙盒，不是主业务启动入口。其 Compose 项目为 `quantmind-dev`，运行数据为 `.local-dev/project/`；不能与主业务栈同时占用 8000。

```bash
bash scripts/local-dev.sh status
```

只有明确需要沙盒、主业务已按维护安排停止且沙盒已有合法初始化状态时，才使用 `bash scripts/local-dev.sh start core`。`full` 增加 worker、数据网关、RSS 和 QuantBot；`research` 需要完整冻结输入与研究设置。不得为启动沙盒覆盖主业务数据、伪造 `READY` 或并发启动两套后端。沙盒的 `restart-backend`、`recreate-backend` 不用于更新 Library 主业务快照。

## 数据与维护边界

- 更新前明确当前运行快照、Compose 项目、镜像、配置与挂载；源码 bind mount 更新和镜像内代码更新不是同一件事，重启不会自动切换已部署版本。
- PostgreSQL、Redis、模型和业务文件须有可核对的备份与恢复方法；Git 历史不是业务备份。不要执行 `down -v`、删除数据目录或重建业务库处理普通启动错误。
- 行情归档、固定研究输入和模型产物分别核对数据身份、日期范围与权限；新数据发布不会自动替换固定研究输入。
- 前端构建见 [Electron 编译](Electron编译方案.md)，数据文件导入见 [QuantDB 数据包](QuantDB_数据包解压指南.md)，训练见 [训练操作](QuantMind_模型训练完全指南.md)，推理合同见 [模型选择](模型推理服务设计与链路文档.md)。
- 供应商 API 与可选券商协议的接入资格、凭据和交易权限仍独立管理；本地业务运行不授权实盘。
