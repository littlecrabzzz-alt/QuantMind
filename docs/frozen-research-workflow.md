# 冻结输入与对照研究

用途：在计算前固定数据、代码、配置和镜像，以离线文件产物运行可复查的 A 股日频对照。入口 `scripts/run_frozen_research.py` 复用训练函数、Qlib 与项目 `CnExchange`，不调用交易接口，也不自动注册平台数据库。平台 API 基线另见[基线流程](quant-baseline-workflow.md)，研究 Agent 操作见[工作台](research-workbench-operations.md)。

## 数据用途与最近半年保留规则

- 新研究先明确训练、早停/验证、搜索反馈、最终独立验证的区间、用途与实际读取范围。最近半年保留作后续验证，不用于日常研究、候选筛选或调参；在课题合同中写出具体起止日期，不能用相对日期或“test”文件名代替边界。
- 候选、输入、执行口径和接受/否决条件冻结后才评价保留区间。已经看过并用于决策的日期只能标作开发比较，不能靠重新命名恢复独立性；若与最近半年保留范围发生冲突，应登记污染并另定未参与选择的验证范围，不能宣称原范围仍独立。
- 这是研究使用规则，不是已经部署的访问控制。当前工具会挂载完整冻结 Qlib 目录，并未按用途强制裁剪读取权限；准备包时须审核实际文件/日期范围和供模型看到的指标，不能仅靠配置日期声称 Agent 看不到最终验证数据。
- 标签的未来覆盖、执行延迟、股票池筛选、预处理拟合及财报/成员历史可得时间均须符合边界。冻结和哈希只证明内容固定，不证明 PIT 或历史市场规则正确。

## 默认开发比较合同

`config/research_controls_cn_l1.json` 明确标记 `development_comparison`，不是独立测试入口：

| 项 | 固定口径 |
| --- | --- |
| 日期 | 训练 2023-01-03—2024-12-31；验证 2025-01-06—2025-03-31；开发比较 2025-04-07—2025-06-30 |
| 股票池 | 训练结束前 60 个交易日成交额中位数选 100 只主板股票，至少 40 日成交；不按比较期收益/流动性筛选 |
| 对照 | 八因子 LightGBM Top20、20 日动量 Top20，均 `n_drop=5`；另列全池等权作市场暴露参考，其持股数不同 |
| 执行 | 1000 万元、95% 目标总仓位、每日决策、次交易日收盘成交；三组同费用/冲击合同 |

此前已查看该比较期，不能解释为最终样本外。实际课题以自己的冻结 `snapshot/config.json` 为准；新包不自动替换旧课题输入，也不能把不同资金或执行包装器的结果当成同一实验。

## 准备、运行与恢复

在项目根目录执行；先确认数据根中存在 `data/quantdb` 与 `db/qlib_data`，镜像及空间足够。以下命令会复制数据或启动实际训练，需有明确研究授权，不能用来探测服务是否在线。

```bash
# 本地沙盒数据与源码分开：显式指定数据根和已存在的计算镜像内容 ID。
python3 scripts/run_frozen_research.py freeze \
  --data-root .local-dev/project --image <本地镜像ID> \
  --output results/my-frozen-comparison
python3 scripts/run_frozen_research.py run --output results/my-frozen-comparison
python3 scripts/run_frozen_research.py verify --output results/my-frozen-comparison
```

可用 `--config <合同.json>` 指定开发比较合同。省略 `--data-root` 从源码根读取数据；省略 `--image` 会查询名为 `quantmind` 的容器，不会自动选择本地 `quantmind-dev`。使用本地沙盒时不要依赖这个默认值。

1. `freeze` 校验切分、目标和资金，复制因子、辅助价格、完整 Qlib 文件、执行代码和配置，逐文件及复制全程检查源内容变化；残留不完整快照不会被覆盖。
2. `run` 把 `/frozen` 只读挂载，只有新输出目录可写；无网络、只读根文件系统，不挂实时数据、数据库或 Docker socket，固定镜像架构、4 CPU、8 GiB 与 Python 哈希种子。
3. 每个信号日单独读取当日特征，使用训练确定的缺失值填充值，与批量评分核对；策略原生读取前一交易日信号，不再多平移一天。
4. 保存模型、信号、净值、实际成交、持仓、运行版本，区分预演与真实成交；逐笔现金、每日资产、净收益和费用独立核对。指数从首笔建仓日收盘比较，Qlib 原生基准另列。
5. 成功后复核快照并写 `completion.json`。对已完成目录再次 `run` 会核验产物哈希并复用；失败重跑创建新 attempt，旧容器/日志保留。单独 `verify` 只核验输入清单，不代表重新核验全部计算产物或策略有效性。

同一目录仅运行一个进程；改变数据、代码、配置或镜像必须用新目录。空间按 manifest 的实际字节数预留，脚本还要求至少 1 GiB 输出余量；历史快照大小不是当前空间保证。`source_commit` 是来源工作区基准，实际执行版本由复制代码内容哈希决定，可能包含当时未提交修改。

## 证据与执行边界

结果应标明开发比较/独立验证阶段、原始数据版本、实际日期/行数、缺口、代码和镜像哈希，以及账务核验结果；缺失结果保持未知。报告文字须与产物复核，收益为正、哈希通过或容器退出 0 都不等于交易准入。

当前基线只接受 CN L1、LightGBM、一天收益标签与次日收盘执行；不能靠改配置将其当作 ETF 月末信号、次日开盘执行器。主板固定涨跌停近似不覆盖创业板、科创板、北交所，也不证明历史 ST、上市初期、退市和财务公告时点正确。估值/成交与资金恒等式见[执行账务合同](execution-accounting.md)。

代码变更后的针对性检查：`scripts/test_frozen_research.py` 与 `scripts/test_frozen_research_worker.py`；后者需匹配实际训练依赖的隔离镜像。检查不代替新的研究授权，不复用真实结果目录。
