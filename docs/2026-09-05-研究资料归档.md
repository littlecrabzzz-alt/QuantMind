## 2. 大语言模型角色偏差与证据判断

### 原文索引

- 标题：*The Analyst in the Prompt: Role, Retrieval, and Memory Biases in LLM Financial Analysis*
- arXiv：2609.03218
- 版本：v1
- 提交日期：2026-09-02
- 摘要页：[arXiv:2609.03218](https://arxiv.org/abs/2609.03218)
- 原文 HTML：[全文](https://arxiv.org/html/2609.03218v1)

### 核心思路

论文研究同一份 SEC 披露材料在不同用户角色或上下文下，模型判断是否发生系统性变化。实验覆盖 3,575 份 SEC 文件和 12 个模型。其重点不是模型能否找到文本，而是用户身份、利益位置或角色提示是否会渗入证据解释阶段，使相同证据得到不同结论。

论文提出的缓解方向包括中性检索、将用户背景与证据处理分离，以及同时输出支持与反对结论；这些方法可以减轻但不能彻底消除角色相关偏差。

### 对 QuantMind 的启发

- 检索层先按问题和客观字段获取证据，不把“我是持仓者”“我看多”等立场写入检索提示；
- 证据卡片和用户画像分开保存，避免用户偏好污染原始证据摘要；
- 对同一结论固定输出支持证据、反证、缺失数据和可证伪条件；
- 若模型用于研报或公告解读，应做“同证据、不同角色提示”的一致性测试。

### 后续验证问题

用中国上市公司公告、问询函和财报构造小样本，对比“中性研究员、持仓者、空仓观察者、风险经理”等角色提示下的事实抽取和投资判断差异。事实抽取与观点判断要分别评分。

## 3. 熵因子模型用于组合复制

### 原文索引

- 标题：*An Entropic Factor Model for Robust Portfolio Replication*
- arXiv：2609.03552
- 版本：v1
- 提交日期：2026-09-03
- 摘要页：[arXiv:2609.03552](https://arxiv.org/abs/2609.03552)
- 原文 HTML：[全文](https://arxiv.org/html/2609.03552v1)

### 核心思路

论文提出两阶段组合复制方法：第一阶段使用熵约束或熵正则化的因子模型估计资产与目标组合的关系；第二阶段由估计结果生成复制组合权重。目标是在估计误差、异常资产和权重稳定性之间取得比普通最小二乘更稳健的平衡。

论文结果需要分情景理解：在正常市场样本中，该方法可能降低换手，但净收益或跟踪误差未必优于 OLS；在部分资产被污染或异常冲击的压力情景中，它会压低问题资产权重，并改善部分稳健性指标。因此它更像“异常数据下的稳健复制方法候选”，不能从摘要直接推出普遍优于传统方法。

### 对 QuantMind 的启发

- 可用于指数增强、ETF 替代、组合跟踪和模型组合权重研究；
- 价值可能主要体现在权重稳定、降低换手和异常数据鲁棒性，而非直接提升收益；
- 实验必须与 OLS、岭回归、非负最小二乘和带换手惩罚的优化器做同口径比较。

### 后续验证问题

在 A 股指数复制任务中同时加入停牌、涨跌停、缺失价格、成分股变更和交易成本，分别比较正常区间和人为污染区间。验收指标包括跟踪误差、最大偏离、换手、成本后收益、权重集中度和异常资产权重。

## 4. QuantConnect 回测日期范围异常讨论

### 原文索引

- 主题：Bug Report: Backtest silently executes a ~1-day window ~90 days before "today" instead of the configured date range
- 平台：QuantConnect 社区讨论
- 讨论 ID：21299
- 首次发布：2026-08-29
- 更新：2026-08-30
- 原文：[QuantConnect Discussion 21299](https://www.quantconnect.com/forum/discussion/21299/bug-report-backtest-silently-executes-a-1-day-window-90-days-before-quot-today-quot-instead-of-the-configured-date-range/)

### 核心思路

发帖者报告回测请求的起止日期与实际运行区间不一致。社区回复指出，组织设置中可能启用了为样本外测试保留最近三个月数据的选项，因此引擎会截断可用回测区间。

这是一条平台排障线索，不足以证明 QuantConnect 存在通用回测缺陷。它的研究价值在于提醒我们：用户传入的参数不等于引擎最终执行的参数，组织级配置、数据权限和样本外保留规则都可能静默改变回测边界。

### 对 QuantMind 的启发

- 每次回测必须保存并展示请求区间、解析后区间、实际首个交易日和最后交易日；
- 数据缺口、预热期、停牌、样本外保留和权限裁剪应分别记录原因；
- 回测报告显示实际样本数、交易日数和首尾行情时间戳；
- API 集成测试应断言实际区间，而不是只验证任务成功返回；
- 若引擎自动调整日期，UI 与报告中必须显式提示。

### 后续验证问题

检查 QuantMind 当前 Qlib 回测链路中日期解析、预热窗口、数据日历和结果报告是否使用同一边界；补一个跨周末、节假日、数据起点不足和预热期的端到端验收矩阵。
