# QuantMind 远端持续研究与策略观察方案

日期：2026-09-08。状态：方案提交；真实 API 接入及流程实施待后续进行，尚未启动新研究或模拟组合。本文记录用户希望并行推进的两个方向，以及基于当前源码核查的驱动方式。

后续验收记录见 [GLM 5.3 / Flash 真实 API 与研究工作流验收](glm-research-validation-20260908.md)。该记录更新真实接入、恢复演练及结果；本文的“尚未实施”描述保留为方案提交时的状态，完整服务内持续研究队列仍未上线。

## 1. 目标与已确认的范围

用户希望在 Token 预算足够时，由远端持续推进工作，同时看到直观的收益表现与研究进展，维持参与动力。两个方向并行：

补充确认：用户要求 **单次无人值守运行不超过 8 小时**，期间可随时查看，没有四小时下限，也不要求超过八小时的连续自主运行。运行窗口内系统自主迭代，不需要持续人工介入；到时保存进度并收尾，下次运行可接续。这是运行与交互的目标要求；本次仍只更新方案，尚未实施或启动服务。

| 方向 | 研究内容 | 交付物 |
| --- | --- | --- |
| 方法研究 | 论文复现、因子增量、模型稳健性、数据与执行验证 | 可复用方法、完整实验记录、有效或无效的证据 |
| 策略研究与观察 | 组合规则、成本与换手、独立验证、固定版本向前模拟 | 历史净值、模拟盈亏、同期基准、超额收益、回撤、持仓与交易记录 |

两条线共享数据与实验工具；研究成果经固定门槛评审后成为新策略版本。既有模拟版本保持不变，升级采用新版本并保留旧成绩。研究、历史回测、向前模拟和真实交易分别记录；本方案不包含真实交易。

以下是实施建议，尚不是已配置的运行参数：方法线约 40%、策略线约 60% 的研究预算；同时最多一个重型训练/回测作业；每批最多两个新候选。批次上限之外还必须设置整个课题的累计尝试上限，不能通过不断新建批次绕过预算和多重试验控制。

## 2. 谁来驱动

推荐采用服务内驱动：Celery Beat 唤醒研究协调逻辑，Celery worker 推进一个有界阶段；需要提出假设或解释结果时调用远端已有的 QwenPaw；确定性工具负责数据检查、训练、回测和核验。状态与产物持久化后再推进下一阶段。

| 角色 | 职责 | 是否必须依赖外部常驻 Agent |
| --- | --- | --- |
| 服务内调度与协调 | 选取课题、检查预算、提交任务、核对状态、恢复与停止 | 否，由云端服务承担 |
| QwenPaw 研究 Agent | 阅读资料与历史实验，提出假设和受限候选，解释结果 | 使用项目已部署的 Agent 运行时即可 |
| 大模型服务 | 为 Agent 提供推理能力 | 现有闭环使用 DeepSeek，仍需其 API、网络和可用额度 |
| 训练与回测 worker | 执行固定输入和配置，生成模型、成交、持仓、净值 | 不需要外部 Agent，也不需要用 LLM 做数值计算 |
| 固定版本策略的每日模拟 | 根据最新合格数据生成信号、模拟成交、记账 | 规则/模型冻结后无需每天让 LLM 重新决策 |
| 人与外部编码 Agent | 选方向、审阅阶段结论、实现新工具、处理越界问题 | 按需介入，不作为持续运行的必备进程 |

因此，Mac 关闭后仍可由云端推进已授权课题。这个行为是目标架构，目前尚未通过长时间运行和断线恢复验收。大模型不可用时暂停需要推理的研究阶段；固定策略模拟在数据、模型和执行服务正常的前提下应能独立继续。

概念流程如下，方括号中的协调层为待实现部分：

```text
方法来源 / 人工登记的策略课题
            ↓
Celery Beat → [持久化研究协调层] ← 用户暂停 / 范围 / 预算
                      ↓
             数据准入与冻结研究合同
                      ↓
            QwenPaw 提出受限实验候选
                      ↓
          确定性训练 / 推理 / 回测 worker
                      ↓
             独立核验与实验结果归档
                      ↓
         下一研究阶段 / 否决 / 等待人工判断
                      ↓ 达到策略准入条件
            固定版本的每日向前模拟
                      ↓
               净值与研究进展展示
```

### 复用 Pipeline 前必须处理的两处语义

1. **生成的代码不一定参与回测。** `use_generated_strategy_for_backtest` 默认 false；`_run_backtest` 仅在开启时传入生成代码，否则构造 TopkDropout 请求。必须保存实际执行的策略、评分文件与配置哈希，不能把“生成了代码 + 回测完成”描述为生成代码已经被验证。
2. **推理带有发布信号的副作用。** `execute_run` 在回测完成前调用 `mark_latest_run` 与 `publish_signals`。实际发布受 `ENABLE_SIGNAL_STREAM_PUBLISH` 控制，且 latest 标记有单独写路径。研究任务应默认不发布、不覆盖现有交易/模拟的 latest，也不修改正式活跃模型。实现时通过明确的研究执行模式和隔离存储/队列约束，不能只在提示词里要求不交易。本轮没有判定云端正在发生信号发布或订单行为。

第一阶段优先复用已受控的冻结实验路径。上述边界未验收前，不把通用 Pipeline 直接接成研究执行器。

## 4. 最小补齐方案

复用现有 PostgreSQL、Redis、Celery、QwenPaw 与实验 worker，增加一层轻量研究协调逻辑。第一版不引入新的工作流平台，也不同时运行外部 Agent 调度与服务内调度两套主控。

### 4.1 课题合同与持久化状态

给每个课题固定 `case_id`、方向、假设、数据要求、股票/产品池、时间切分、基准、成本、验收/否决条件和累计预算。每个实验记录父实验、候选原因、输入快照、Git/补丁哈希、镜像、参数、随机种子、任务与容器 ID、数值产物和校验摘要。

建议用版本化 SQL 迁移新增最小课题/阶段记录，引用已有 Pipeline 或冻结实验 ID；不重建现有实验执行系统。现有文件案例与来源指纹保留并关联，不能在两个地方维护互相独立的主状态。

建议阶段为 `registered → data_review → ready → proposing → experimenting → verifying → review`。数据不足进入 `blocked_data`；有界研究完成进入 accepted/rejected；暂停、预算耗尽、运行失败和等待人工输入分别记录。`data_review` 与 `review` 优先由固定规则自动判定，不表示每次等人批准；只有规则无法判定或需要扩大授权时进入 `needs_user_input`。策略的 paper 状态是另一个生命周期，不能把研究 accepted 自动解释为允许真实交易。

### 4.2 有界推进与恢复

- Beat 唤醒协调器，worker 一次推进一个阶段并落盘，不维持无限增长的聊天上下文。
- 提交前持久化 intent；按课题、阶段和配置指纹生成稳定幂等键。数据库唯一约束与原子状态更新防止重复领取，租约/心跳识别失联 worker。
- 返回任务 ID 后保存映射；请求超时先查已有任务/容器/产物，不能直接重发。服务重启恢复状态后，先协调存活子任务，再决定继续、核验或标记失败。
- 复用已有实验文件锁和防重复逻辑，但它们不能替代跨 Celery worker 的课题锁与状态机。
- 人工可分别执行“停止新增实验”“暂停后续推进”“取消当前计算”；取消确认必须核对实际子进程/容器，不能只停止 SSE 或聊天。
- 固定输入、代码和工具版本；正常研究中不得修改评估口径、服务代码、依赖或原始数据。新工具需求转为单独开发事项。

### 4.3 预算和资源

- 课题、批次与每日分别设置时间、调用/Token、实验数和计算预算。具体额度在实施时配置，本方案不授权持续扣费。
- 提交前预留资源和调用预算；调用后记录真实用量，区分输入、输出与缓存读取。中断缺失用量记 unknown，不能当零消耗；预留不足停止新调用。
- 重型作业初始并发为 1；方法阅读可以与训练等待交错进行。模拟更新优先获得运行窗口，训练服从服务器实时内存/CPU条件。
- 模型输出只能提出允许的变更；JSON/参数校验和数值门槛由程序决定。数据不齐、会计核对失败、预算耗尽时停止受影响课题或共享依赖对应的工作；在剩余授权和预算内继续其他独立课题，不因单个阻塞停掉全部研究。

### 4.4 独立验证与策略准入

- 开发、早停/选择与最终验证用途分开；整个课题累计登记所有尝试及数据接触记录。已经反复观察的 2025 年 4–6 月区间保留为开发区间。
- 最终留出评估在候选和门槛冻结后按协议执行；不能把结果再喂回无限调参，并重复宣称同一区间独立。
- 验证历史股票池/行业归属/公告可得时点、标签结束时间、交易日、价格与复权、停牌/涨跌停、整手和费用。
- 程序独立核对现金、持仓、成交、费用与净值；Agent 文字与数值产物不符时不通过报告复核。
- Strategy Lab 的 overfit 分数不是自动准入标准。其回测引擎、时间切分和统计检验需与正式合同对齐后才能复用。
- 研究候选进入模拟前核验同一规则在历史重放和每日执行中的一致性。模拟生命周期、账本与研究记录相互关联，但隔离输出和活跃策略状态。

### 4.5 单次不超过 8 小时的自主运行约定

每次运行在启动前固定不超过八小时的截止时间，以及课题范围、预算、工具权限、验收标准和允许自动推进的阶段。可以提前完成、停止或查看，不设最短时长；单个实验应服从整个运行窗口。窗口内尚有合格任务和预算就自主继续，普通检查点不暂停等人回复。到达本轮截止时间后保存状态并结束本轮，不因用户未回复而自动延长或启动下一窗口；后续启动从已保存进度接续。

截止时间包括必要收尾。调度器应预留可配置的收尾时间，拒绝预计无法在剩余时间内完成和收尾的新实验；对仍未结束的任务使用已验证的检查点或取消路径，核对实际子进程状态。恢复运行不能重置本轮截止时间，不能只关闭聊天而让计算无限延续。八小时以上的连续自治不在本次实现和验收要求内。

- 一个实验完成后，程序先核验产物，再让 Agent 读取结构化摘要，解释结果并选择下一候选、结束当前假设或切换到已授权队列中的下一课题。负结果正常归档，不作为需要人工处理的异常。
- 每个有界批次结束后自动生成摘要并选择下一步；两候选的批次上限不代表必须等待人工解锁。累计课题/每日预算、独立验证规则和停止条件继续生效。
- 数据结构与语义均有已验证合同且满足准入时自动推进；无法证明历史可得性等问题转为阻塞，不能由 Agent 猜测通过。已授权数据源可按固定采集/发布流程补齐并重新检查，不在正在运行的实验里切换输入版本。
- 策略模拟的自动准入可在启动合同中预先允许：固定门槛、会计与执行一致性核验全部通过后创建独立模拟版本；不更换现有观察版本、不引入真实订单。没有预先允许的晋级停在候选归档，其他研究继续。
- 一个课题失败或受阻时释放资源并调度其他合格课题；所有课题都受阻、完成或耗尽预算时待机，不用重复读取同一资料、反复改写报告或空转调用模型填满时间。
- 每轮只加载课题合同、近期结果、累计尝试索引、下一步计划与必要证据。完整历史在持久化存储中按需检索，避免无限聊天上下文引起用量失控或遗忘既有失败。
- 模型负责假设和解释，程序负责边界、状态转换和数值判断；实现新工具、修改运行服务或扩大数据/策略范围汇总到下次人工检查，不让研究 Agent 临时改动正式服务。

### 4.6 故障处理与自动恢复

下表为待实现的处理策略，不表示现有运行时已经具备。重试次数和退避上限由配置固定，并计入原预算；不能通过重启或新建任务清空失败计数。

| 情况 | 系统自主处理 | 人工介入条件 |
| --- | --- | --- |
| 模型限流、网络短暂超时 | 对可安全重试的调用限次退避并加入随机间隔；等待期间推进其他阶段 | 凭据失效、额度不足或持续失败超过阈值时暂停依赖该模型的工作并汇总 |
| Agent 输出 JSON/参数不合格 | 返回明确校验错误，允许有限次重新生成；不放宽工具和门槛 | 反复失败则标记当前阶段失败并换课题，需变更工具/范围时才请求决定 |
| 提交训练后的返回丢失 | 按稳定任务 ID、容器和产物协调；结果不明时保留 uncertain，禁止重复提交 | 状态无法确定且自动核对路径耗尽时隔离该实验；如计算资源未释放则保留资源占用记录 |
| worker/协调服务重启 | 恢复持久化状态、确认租约失效并阻止旧 worker 继续提交状态；接管可确认的存活任务或继续下一阶段 | 不能证明任务归属/状态时暂停受影响任务，不强行重跑 |
| 卡死、超时、内存不足 | 按阶段超时和心跳处理；先核对外部任务，再终止确认归属的进程/容器。仅在输入与研究语义不变、失败类型允许时限次重跑 | 需要改变研究合同、资源超出预算或重复失败时转阻塞；不能自动缩短样本以“跑成功” |
| 行情未更新或数据校验失败 | 等待数据就绪，隔离坏分区，跳过不合格实验；模拟明确显示数据滞后，按既定规则暂停新增交易 | 需要新数据源、购买权限或修改数据合同才需决定 |
| 实验结果不改善 | 记录否决理由；按预设规则尝试下一假设或结束课题 | 不需要人工；不能降低验收门槛或重复使用最终留出区间 |
| 会计核对失败、输入哈希变化 | 隔离产物，禁止晋级；暂停受同一输入或执行器影响的任务，健康且独立的课题可继续 | 需要修复数据/执行器时集中提交问题；不能让 LLM 用解释替代核验 |
| 数据库不可用、锁/预算无法可靠读取 | 停止新副作用，保留并观察已运行任务；恢复后先协调状态，不盲目启动新任务 | 持续故障或无法协调时告警；正常的短暂故障自行恢复 |

运行监控应区分“仍有心跳”和“取得实际进展”：轮询次数、改写报告和返回 HTTP 200 都不能算研究进展。阶段超时可按实验类型设置，避免把正常长训练误判为卡死。

### 4.7 用户检查页面与通知

每个批次完成、状态显著变化以及本轮结束时更新检查摘要，用户在八小时以内的任意时间都能打开查看，不设置四小时下限或固定四小时通知。摘要更新与任务循环解耦。默认更新页面/文件即可，不自动向外发消息。仅持续故障、所有工作受阻、预算耗尽或需用户决定时形成明确提醒；具体通知渠道另行配置。

每份摘要必须回答：这段时间完成了什么；哪些假设被保留或否决以及证据；策略净值和基准变化（有新交易日数据时）；用了多少预算；自动恢复了哪些故障；当前任务与下一步；最多三个需要用户决定的问题。没有新行情时展示最后数据时间，不制造小时级投资收益变化。

用户只需调整方向、预算或处理例外，无需逐项批准候选和普通重试。提供暂停全部新增研究、暂停单课题、取消当前计算和调整后续优先级的入口；预算增加和研究合同修改保留版本记录，不追溯改写已完成实验。

建议观察榜展示策略版本、证据阶段、模拟起始日、观察天数、数据截止日、虚拟本金、累计盈亏、同期基准盈亏、扣费超额、最大回撤、换手与费用。历史回测曲线与启动后的向前模拟曲线分栏；基准和策略使用相同日期与资金口径，缺数据标记滞后，不伪造更新。

建议第一组为简单动量与八因子模型，保留同池等权作为对照。可采用 10 万元虚拟本金，但这是待配置建议；现有冻结实验使用 1000 万元，不能把旧结果按比例缩放后冒充 10 万元账户的可执行收益。整手、现金和最低费用会改变结果，应按目标资金重新运行并核验。

建立三个可比较的长期账本前，先验证现有模拟服务是否支持独立多组合及其持久化。当前用户/租户活跃策略键不能直接当作多策略排行榜的账户模型。若需扩展，优先增加明确的 portfolio/version 身份和隔离键，不为每个策略伪造用户。

研究进展记录成功复现、发现数据缺口、否决前视结果、减少成本、通过独立验证等里程碑。它们不是现金奖励，也不混入投资收益。失败/退役策略保留，所有试验可追溯；不按实验次数或最高回测收益奖励 Agent，避免鼓励重复搜索和过拟合。

策略每天可能亏损。产品应解释组合变化、基准差异和成本影响，不能承诺每日正反馈。研究进展可立即积累，向前模拟证据必须随真实交易日积累。

## 7. 实施顺序与验收

| 阶段 | 最小成果 | 必须验证的行为 |
| --- | --- | --- |
| 0：接口与数据准备 | 一个冻结课题合同，明确选择受控 worker；完成模拟链与信号隔离检查 | 正式数据只读输入、研究无发布副作用、执行规则与实际资金一致 |
| 1：远端单课题闭环 | Beat → 协调阶段 → QwenPaw → 有界实验 → 独立核验 → 归档 | 真正调用工具、证据完整；重复投递无重复实验；断开观察端不影响服务器 |
| 2：恢复与边界 | 重启协调服务、模拟 API 超时、暂停/取消、预算耗尽 | 能识别存活任务；不盲目重发；已完成阶段不重复扣费；计算停止有证据 |
| 3：双线与每日模拟 | 方法与策略队列公平推进，固定版本账户按日更新 | 重型并发受限；新研究不改旧策略；成交/现金/净值闭环；LLM不可用不阻塞固定策略 |
| 4：观察与反馈 | 收益榜、研究里程碑、阶段报告 | 历史/模拟分开、基准可比、负面结果保留、数据滞后可见 |

首次验收先完成隔离环境下的恢复与边界检查，再进行一个预算固定、**总时长不超过 8 小时的无人值守验收窗口**。不要求跑满八小时，也不要求验证八小时以上的连续运行。中途无需逐轮确认；在本轮截止前保存状态并完成收尾，下次启动可从已保存状态接续。该验收尚未执行。以流程可靠和产物真实为通过条件，不为追求收益临时增加候选。短期模拟只证明系统运转和产生新观察，不证明长期盈利。

补充验收要求：

- 无人工催促完成至少两个相继批次，能说明前轮证据如何改变后续选择；提前遇到固定停止条件则如实记录，不能为凑批次数破例。
- 在隔离验收环境注入模型短暂不可用、worker 重启和提交响应丢失，确认不会重复实验、重复模拟交易或覆盖产物；真实研究数据不可用于破坏性故障注入。
- 单课题 blocked 后另一个独立课题仍能推进；共享执行器故障时正确扩大暂停范围。
- 窗口内检查点自动留档并继续合格任务，不等待用户逐轮回复；达到本轮截止时间或预算上限后收尾，不自动延长或开启新窗口。没有可做工作时提前结束并保留状态。
- 预算与任务所有权在进程重启后仍有效；没有自动重放已经完成的 LLM/计算阶段。无法获取实际费用时明确记录未知用量，不宣称精确的零重复计费保证。
- 用户在本轮任意查看时点仅阅读摘要即可定位产物、预算、阻塞和下一步；暂停/取消入口有效，实际子任务状态可核验；截止时间经过重启后仍有效，临近截止的任务不会越过收尾边界。

日常研究结论与验证完成更新检查摘要；需要用户采取行动的持续故障、全部阻塞或预算问题按 4.7 节提醒。本次不创建任何自动化、通知或长期运行任务。

## 9. 真实 API 验收与后续低成本研究

用户要求先提交方案，之后提供 Token/API 接入信息，使用真实 API 跑通流程。接入时需确认服务地址、模型标识、凭据所在的受保护配置位置，以及首轮费用或 Token 上限。密钥只进入 Git 忽略的本地/远端配置，不写入本文、日志、提交或研究产物；不在缺少接入信息时擅自选择其他账户消耗额度。

真实验收分步推进：

1. 用少量调用验证连接、模型、工具调用与用量字段；确认实际计费口径和可用权限。
2. 补齐并验证最小协调逻辑，在隔离环境完成故障恢复与边界检查，再跑一个小型真实研究闭环；模型回答必须对应真实实验与独立核验产物。
3. 依据实测耗时和单实验成本设置预算，在不超过八小时的窗口内验证自主迭代、持久化、预算停止与收尾。时间是上限，不是消费目标。
4. 给出完整报告：模型调用次数、输入/输出/缓存 Token、已知实际或估算费用及其依据、计算耗时、候选数、有效/无效结论、自动恢复次数与人工介入次数。计费用量缺失单独标记，不把提供商未返回的数字当作零。

后续低成本长期研究以可接续的短窗口累积结果，不以一个无限聊天会话持续运行。当前不要求实现八小时以上的连续自治；将来如需按日/按周自动启动多个窗口，另行明确总周期、累计预算和调度授权。

成本控制优先级：确定性计算与状态轮询不用 LLM；按数据更新和任务完成触发分析；优先复用可核验且输入/代码/配置完全一致的产物；使用短摘要和索引检索替代整段历史反复输入；减少无收益的重复候选；没有新证据时待机。模型分工、缓存收益与并发上限根据真实 API 的能力和账单选择，不预先假定廉价模型足够可靠。

低成本是待衡量的目标。以“每个完成核验的实验/课题成本”和“每个有证据的新结论成本”评估效率，同时展示失败尝试的全部开销；不只报告成功实验的费用，也不以降低数据准入和独立验证标准换取表面成本下降。
