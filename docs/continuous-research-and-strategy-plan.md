## 1. 目标与长期约束

从产品页面建立课题，讨论清楚后明确确认执行，支持两个方向：**量化策略链路**与**方法 / 新因子研究**。两条线共享数据合同与确定性实验工具；方法产物可成为策略输入。用户能看到可核验的进展、相对基线的变化与失败原因，之后逐步增加固定版本的向前模拟观察。

- 每次无人值守窗口不超过 **8 小时**，无 4 小时下限；提前完成即结束。窗口内自主推进，普通检查点不等待逐轮确认。
- 支持本机隔离沙盒与云端实际计算；关闭浏览器不停止任务。Mac 休眠/关机不能保证本地继续，离机运行用云端。
- 状态、已完成实验和累计尝试跨窗口保留。当前通过用户审阅并确认继续计划开新窗口，不因用户未回复自动延长。未来周期启动需明确总周期、累计预算和停止条件。
- 用户已授权所提供真实 API，本次验收无金额/Token 总额限制，允许 429 退避；时间是上限，不以耗满额度为目标。后续窗口仍受课题与计算尝试限制。
- 研究、开发回测、独立验证、向前模拟、真实交易分别记录；本方案不包含真实交易。缺失费用记未知，失败记录保留。

## 2. 当前版本：已经交付什么

状态基于已提交源码及 2026-09-09 验收，并不替代每次启动前的能力检查。

| 能力 | 当前实现 | 边界 |
| --- | --- | --- |
| 产品入口 | 新问题/材料/已有结果建课题；讨论、计划版本、缺项检查、明确确认、执行记录与控制 | 能讨论新对象，不代表已有任意数据或算法执行器；缺项保持准备状态 |
| 人工介入 | ask 只回答；修改申请暂停并生成新版本；确认后才启动/继续 | 不能在旧结果上静默更换研究目的、数据或门槛；模型计划仍需人工审阅 |
| 策略研究 | 基线 → 有限特征子集/模型参数候选 → 真实训练、逐日推理、CnExchange 回测 → 核验 → 双倍费用压力实验 | 尚不允许任意策略代码、持有期/组合规则修改 |
| 方法 / 新因子 | 输入公式或模型提出公式，实际计算因子值；覆盖、分期 IC/Rank IC、分层/相关性与组合增量 | 原八项特征上的受限因果公式；不自动实现任意论文算法，也不自动获取论文正文 |
| 两方向关联 | 可基于方法执行的结果建立讨论课题，保留来源 run_id；给定公式可进入方法计划首个候选 | 旧直接因子转策略入口已关闭；现有底层引用校验仍保留，新界面先讨论/审阅，不自动覆盖策略 |
| 服务内驱动 | 专用 Celery research-worker/Beat，PostgreSQL 课题与窗口，Redis 队列 | 不依赖外部常驻编码 Agent 或浏览器；本版直接调用配置的模型 API，未走旧 QwenPaw 主控 |
| 有界恢复 | 幂等创建、租约、固定容器名、模型退避、暂停/取消/继续、绝对截止 | 无法确认计算状态时保留证据并要求检查；不能保证所有故障都自动修复 |
| 本地与云端 | 同一页面/API，按后端节点身份绑定账户和任务；本地数据在沙盒 | 无自动跨节点课题迁移或结果回灌 |
| 操作反馈 | 点击记录显示加载并定位详情；重复点击也定位；轮询不抢滚动位置 | 旧静态页面需要刷新才能载入新发布资源 |

默认 **2 小时、计划默认 1 个候选（至多 2 个）、glm-5.3-flash**；可选配置中的 GLM-5.3。候选上限随课题合同固定，继续窗口不重置累计候选计数；每课题最多 12 次实际计算尝试，每节点同时一个重型实验。两方向可登记并交错推进，不表示同一节点同时并发多个训练。

当前产品中的“策略链路完成”表示冻结模板的训练—推理—回测—核验闭环完成；独立数据验证与每日向前模拟仍待开发。

## 3. 实际驱动与恢复方式

```text
研究工作台：新问题 / 材料 / 已有结果
          ↓ 保存草稿、讨论问题、形成计划版本
数据 / 工具 / 待决定事项检查 → 有缺项：保留准备方案
          ↓ 用户审阅并明确确认可执行版本
          ↓ 认证 + 节点身份 + 幂等事务
PostgreSQL：课题合同 / 运行窗口 / 检查点
          ↑↓
专用 Beat → 研究协调器 → 模型 API：提出候选 / 解释选择
                 ↓ 已校验且持久化的实验方案
          隔离 Docker：训练 / 因子计算 / 逐日推理 / 回测
                 ↓
          独立账务与产物哈希核验
                 ↓
          下一候选 / 压力实验 / 完成报告 / 阻塞
```

确定性状态推进、计算和账务不用 LLM。模型输出不能直接执行任意代码，也不能替代数值门槛。新工具需求转为开发事项；正常研究不得自己修改源码、依赖、数据或评估口径。

暂停完成当前实验后停止后续；取消/到期须确认所属计算停止。协调进程恢复时先核对持久化意图与原容器，不能盲目重跑。模型在途超时允许按期限退避重试，未知用量保留；计算幂等与模型计费是两个问题，不宣称精确的零重复计费保证。

正式数据仍由云端管理；Mac 只用已核验固定快照。复用受控冻结执行器，尚未把通用 Pipeline 作为本版研究执行器：后者的生成代码是否实际回测、latest 标记及信号发布副作用，接入前必须单独验证。原因子演化、研究采集和模拟服务存在，不代表已经接入本协调器。

## 4. 目前的验证证据与缺口

双端真实完成：云端策略与本地方法各 3 实验、9 组组合；经产品 API 下载 **135 个产物**并校验哈希，独立复算 **18 组组合账务**。已验证关页面后继续、计算中 worker 重启接回原容器、真实取消、暂停与因子转策略引用；隔离数据库并发/归属/租约检查通过。

本地候选在开发区间的净收益由 13.7316% 提高到 15.0805%，但单因子验证期 Rank IC 为负。这是组合开发增量，仍标记 `needs_independent_validation`，不是独立发现或盈利证明。详细课题、Token、失败与未知用量均见验收记录，本文不重复完整账本。

尚未完成的验收必须保留：连续多小时稳定运行、整机断电/休眠恢复、磁盘故障、真实供应商连续限流下的恢复，以及全自动跨窗口连续研究。截止机制有 15 秒真实强制停止测试，不等于跑满八小时；浏览器下载事件验收曾超时，报告 API 下载/哈希通过，不能混为一项成功。

## 5. 后续迭代路线（2026-09-12 重排）

优先级从“完善模板和报告界面”改为“交付完整 Agent 的一条真实工作链”。详细设计见第 8–16 节。本轮仅设计，不自动启动新研究。

| 阶段 | 必须交付 | 退出条件 |
| --- | --- | --- |
| A：持久 Agent 与真实工具 | 会话、工具循环、独立控制通道、消息收件箱、事件回放、课题文件；接入数据读取、代码运行与实际回测 | 在同一会话中，Agent 根据工具结果决定下一步；能打断实际子作业，消息可追踪是否生效，刷新后能继续 |
| B：平台成果闭环 | 新因子/新策略代码、因子版本、演化任务引用、回测记录、双向来源链接 | 一个从新想法开始的真实案例，在因子库和回测页打开同一成果；中途修改产生可辨认的新版本 |
| C：开放研究与持续迭代 | 材料读取/公开来源检索、数据准备、受限沙盒编码与修错、分支比较、独立验证 | 另一案例从材料开始完成方法实现及对照实验；不套用八因子模板，失败或数据缺口也有实际证据 |
| D：无人值守与成本验收 | ≤8h 窗口、模型/计算分离、恢复/限流/截止、跨窗口累计记录 | 在隔离环境通过数小时真实运行和故障演练；控制延迟达标，停止有证据，无无界重试或重复实验 |

**A+B 构成第一个对用户交付的版本，不能仅交付 A 的聊天界面便称为完成。C+D 是用户所要求完整能力的必做范围，不以“以后可扩展”代替。** 分阶段用于验证，每阶段都写实际证据；固定版本每日模拟和已约定的项目共享另行接入，研究完成不会自动触发模拟或交易。

## 6. 怎样提供直观反馈并控制长期成本

当前可看历史净值、扣费收益、回撤、实验门槛和事件记录。后续增加研究里程碑：真实复现、排除一个假设、找到数据缺口、通过独立验证、减少成本。奖励来自有证据的新结论，不按调用次数、实验数量或最高回测收益排名。

向前模拟上线后，单独展示策略版本、观察天数、虚拟本金、累计盈亏、同期基准与净超额、回撤、换手及成本。历史回测与模拟分开；失败/退役版本仍保留。若改用 10 万元虚拟本金，应按整手、最低费用和现金约束重新执行，不能将现有 1000 万元结果线性缩放冒充账户收益。不承诺每日正回报。

低成本路径：只在新证据/实验完成时请求模型，输入结构化摘要；去重候选，按输入/代码/配置完全一致的哈希复用可核验产物；没有工作时待机。当前 Flash 为默认，旗舰模型是否只用于难题审查要通过扩大对照评测决定，不把单次速度或套餐活动当长期成本结论。接入方式及套餐权益沿用 GLM 文档中的核查边界。

周期研究未来只在完成、有价值结论、持续故障或需用户行动时通知；不发送无变化心跳，不要求用户持续盯守。通知渠道、自动启动周期、总预算和模拟准入尚未配置。每次迭代衡量“每个已核验课题/新结论的总成本”，包含失败与未知用量。

## 7.1 讨论与执行的交付边界（旧版记录，2026-09-12 更正）

旧版改善了误触启动与计划版本控制，但没有解决“输入不知道填什么、研究过程不清楚、无法有效介入”的完整产品问题。新主题可从空白问题或材料开始；研究助手结合原输入、当前计划、近 12 条讨论和实际执行证据整理计划。原输入始终保留，计划追加版本；用户提问不会改变执行，调整计划必须经过新版本确认。这种独立规划调用仍不是持续工作的 Agent。

可执行性不是模型文字中的“可以”：代码检查数据模板、工具、字段、公式、准备缺项、待决定问题以及确认时的库存版本。计划和新窗口在同一事务写入，避免已启动却没保存确认；并发确认同版本只返回原执行。这里的程序检查仍不自动证明自然语言计划的科学价值或承诺成立，用户需核对对象和范围。

当前不会自行编写任意新算法、抓新数据、把论文变成已验证策略。此类主题可以完成讨论和准备方案，接下来须落实具体工具/数据并补验证后再开放对应执行器。原来的因子演化、因子库、回测页面保留，未自动全接入本研究协调器。

## 8. 用户实际使用的产品

### 8.1 从想法进入，不要求先有策略或因子

统一入口叫“研究”，内部以课题组织。因子库、策略、回测、资料页面上的“交给 Agent 研究”进入同一会话，并携带所选对象的版本；不再创建互不相通的聊天工具。旧研究记录仍可查看，不能自动恢复其已停止的执行。

新课题支持自然语言、粘贴材料、论文/网页链接、文件附件、平台对象引用。用户可以只说“我想研究行业轮动”，不要求用户懂公式、填写工具名或先创建策略。Agent 先查平台实际数据和能力，提出一两个可验证的问题，并说明研究对象、准备怎么验证、会交付什么。涉及方向选择时一次只问真正影响下一步的关键问题，已知资料不反复询问。

例：“我想研究成交量是否能过滤动量策略的假信号。”Agent 应先确认市场/可用数据，找到相应价格与成交量字段，提出“原动量策略 vs 增加成交量过滤”的实验和明确成果。若该市场缺数据，展示真实缺口，提供取得数据或调整问题的选项；不能默默改成固定股票池的参数调优。此例仅描述交互，不是当前已取得结果或默认启动的研究课题。

输入内容逐步成为可编辑的任务约定：研究问题、对象/范围、材料、基准、评价方法、预计产物、执行节点和最长时长。用户可直接用消息修改，结构化字段由 Agent 整理并显示差异。默认空值保持“待确定”，不以模型猜测冒充用户要求。

初始处于讨论状态：可以读取已授权的平台资料和整理计划；可选公开检索范围由会话权限显示。用户看见准备研究的具体内容后，点击“按这个方向开始”。授权的是范围内的自主研究，包括查数据、写实验代码、修错和多轮比较，不是逐个工具调用都确认。改变市场、目标、评价区间或扩大权限/时间时另作明确决定。

### 8.2 一个持续工作的会话，而非提交表单后等报告

页面主体是对话和真实工作过程，文件和结果是随时可打开的侧栏，不自动把整份技术报告塞给用户。

| 页面位置 | 用户看到什么 | 可做什么 |
| --- | --- | --- |
| 顶部任务栏 | 当前问题、对象、节点、正在执行的动作、窗口剩余时间、最近活动时间 | 立即打断、暂停后续、继续、结束本课题；检查当前执行约定 |
| 中间会话 | 用户消息、Agent 简短行动说明、工具活动卡、结果与下一步决定 | 追问、引用某个结果、要求改方法、补充材料 |
| 当前工作卡 | 例如“正在检查成交量缺失”“正在运行候选 B 的回测”；排队/运行/重试分别显示 | 展开参数、数据版本、日志和真实作业；单独停止子作业 |
| 任务清单 | 准备验证的问题、已完成/进行中/暂缓的步骤和依赖 | 修改优先级、删除后续步骤、查看 Agent 调整原因 |
| 文件与成果栏 | 材料、代码版本、数据检查、因子、回测、比较结果 | 预览、下载、查看 diff、进入对应平台页面 |
| 需要你决定 | 具体选择及其影响，关联当前证据 | 回复后继续；未回复时暂停依赖该决定的工作 |

工具活动卡至少显示：做什么、为什么需要这一步的简短说明、使用哪份输入、何时开始、实际进度/等待原因、最终输出。展开后提供准确工具名、参数摘要、退出码与日志，不展示凭据。模型自己描述“已回测”不能生成成功活动卡，必须有实际工具事件和有效结果。

研究没有可可靠估计的总百分比；展示步骤状态、实验数量和剩余窗口。只有训练器等提供真实分母时才展示该子任务百分比。时间线显示行动与证据支持的决定，不依赖模型私有推理内容，也不把连续输出文字当作进展。

### 8.3 中途发消息、打断和讨论

输入框始终可用，默认按钮“发送”。旁边保留“打断并发送”；停止按钮始终固定可见。用户无需学习命令语法。

| 行为 | 必须实现的语义 |
| --- | --- |
| 普通提问：“为什么用这个基准？” | 立即持久化、尽快读取，基于截至某个事件的真实状态回答；不改运行合同。重型计算可以继续，回答不必等回测结束 |
| 补充资料：“这篇文章也参考一下” | 记录新材料及来源；在下一次决策前读取。显示已收到/已读取及实际使用在哪一步；涉及改变假设则生成任务调整 |
| 调整指令：“先别调参，先检查数据泄漏” | 收到消息后阻止新的自主工具派发，解释如何调整，记录计划差异；范围内修改沿用已有授权。默认让当前计算完成后暂停，用户可直接选立即打断 |
| 打断并发送：“这个方向不对，先停，换个思路” | 控制通道立即使旧执行版本失效并停止所属活动工具，随后在已暂停会话里处理消息；不等 LLM 识别到“停”才停 |
| 暂停后续 | 不再派发新工作，当前可完成的计算保留；显示“正在收尾”，确认全部所属工作结束后才显示“已暂停” |
| 立即打断 | 取消模型请求、终止/取消当前工具及子作业；保留输出和检查点，可讨论并恢复。远端模型可能仍计费，迟到结果不得触发新动作 |
| 结束研究 | 停止全部所属工作及后续窗口安排，保留成果和历史；不自动删除，也不在新消息到来时偷偷恢复 |
| 继续 | 从最近有效检查点继续；展示未完成工作和剩余授权。输入/代码/方法已变则生成新实验版本，不篡改原实验 |

消息状态区分 `received`（服务已保存）、`read`（进入 Agent 本轮上下文）、`applied`（具体计划/动作已改变）、`answered`（问题已回复）、`needs_decision`（等待用户选择）。每条回复/变更关联原 `message_id`；不能只显示一个发送成功勾号。

自然语言普通发送可能不易区分“提问”与“改方向”：存在待读取消息时先阻止下一次自主派发；读完判定为提问再放行。需要即时停止当前耗时工作的用户可用“打断并发送”，由程序直接执行。混合消息可既回答又调整，不要求用户切换两个互斥聊天模式。

用户缩小范围、减少计算、禁止某动作立即生效；扩大范围/时长/权限才需新授权。允许 Agent 在范围内改实验步骤和修代码，不能沿用旧版“每次修改都重走整张确认表”的交互。

## 9. 完整 Agent 的工作能力与边界

采用**一个服务内主 Agent + 平台工具 + 隔离代码工作区**。主 Agent 自主选择下一步，调用工具，阅读结果，修复错误、改变假设或结束；实验步骤不固定为“基线→两个候选→报告”。确定性程序负责工具权限、数据和数值计算、任务控制与持久化。固定实验流程仍可作为一个工具供 Agent 选择。

| 能力 | Agent 实际能够做的事 | 产出与失败处理 |
| --- | --- | --- |
| 理解与规划 | 从想法/文章/平台结果提取问题、提出可证伪假设，维护计划与待决定事项 | 任务约定、假设、来源引用、计划版本；不清楚先定位问题 |
| 资料研究 | 检索已存资料和公开来源，读取正文/附件，提取方法、公式和依赖 | 原始材料引用、获取时间/哈希、方法笔记；只有摘要时明确缺正文 |
| 数据准备 | 查询目录与 schema、检查覆盖和时间可得性、生成派生数据、调用允许的数据准备作业 | 固定数据清单、质量检查、缺口；已有采集权限内可补数，新增供应商/凭据/费用另行授权 |
| 编码与调试 | 在课题目录读写 Python/配置/测试，运行命令、查看错误、修改并重试 | 代码文件、diff、依赖版本、运行日志；不局限于八因子公式，不改共享应用源码 |
| 因子研究 | 实现新因子、调用演化工具、检查覆盖/IC/稳定性/相关性/消融/组合增量 | 因子版本与评估记录，保留无效候选和失败解释 |
| 策略研究 | 实现选股/持仓/调仓/成本方案，训练、推理、回测、比较并调整 | 策略版本、模型/预测引用、成交/持仓/净值和比较记录 |
| 证据评价 | 使用程序计算结果判断支持、反证或无法判断；设计下一实验 | 每个结论链接实验和评价口径；不只追最高收益 |
| 持续记忆 | 记住用户决策、已试方案、失败原因、数据和代码版本 | 可查看的课题摘要及来源；跨窗口不重复做已完成工作 |
| 自主推进 | 在授权范围和时间内继续有价值的工作，失败时修错或换路线 | 新证据到来才推进；缺决定/权限时等待，耗尽时间时收尾 |

“完整”指上述工具驱动的闭环和人工协作能力。工具未接入或数据确实不存在时，Agent 能定位并处理缺口；不能保证所有论文/市场都可复现，更不能用通用聊天把未执行描述成完成。新增方法只要能在已授权沙盒与数据中实现，就应由 Agent 编码尝试，不能一律退回人工开发。

AlphaAgent/RD-Agent 可作为因子演化子作业，由主 Agent 发起、读取阶段和产物、取消；不先搭建多角色互聊系统。其控制和产物合同必须与其他工具一致。外部交互式 Agent 不承担产品的常驻调度；更换底层模型不会改变会话、工具记录和成果身份。

## 10. 输入、输出和平台联动合同

### 10.1 输入不是一个 prompt 字符串

课题上下文包含：原始消息与附件、用户决策、目标与当前假设、资料引用、平台对象版本、固定数据清单、能力与权限、代码工作区、已完成实验及预算。Agent 可逐步补齐，开始昂贵计算前必须明确该实验的数据、评价和预期输出。

能力目录由实际工具适配器和节点检查生成：名称、输入/输出 schema、可用数据、权限、副作用、预计资源、取消/恢复方式。未通过接入验收的工具显示“尚未接入”，不能仅靠提示词宣称可用。接口存在和数据下载成功都不等于研究就绪。

### 10.2 每一步留下能打开、能接着用的东西

| 成果 | 内容 | 平台联动 |
| --- | --- | --- |
| 研究材料 | 正文引用、文件、公式提取、来源与读取限制 | 课题资料栏；可作为下一课题输入 |
| 数据检查 | 字段/日期/对象覆盖、缺失、PIT 证据、数据清单 | 数据页面的固定版本/检查详情 |
| 实现代码 | 因子/策略/方法代码、配置、环境锁定、测试和 diff | 课题工作区预览；策略草稿进入现有策略/IDE 存储入口 |
| 因子成果 | 定义/代码版本、值文件、评估与状态 | 因子库候选记录；显示来源课题和演化任务，可继续回测或演化 |
| 策略成果 | 完整规则或可执行代码、使用的因子/模型版本、参数 | 现有策略存储中的新草稿版本；不覆盖生效版本 |
| 实验/回测 | 输入、代码、费用、训练/验证划分、预测、成交、持仓、净值、指标 | 真实回测详情；可比较、复算、作为后续研究输入 |
| 比较与结论 | 基线/候选、分期/成本/消融、已支持或已否定的假设 | 课题比较视图；每项指标点开对应实验，缺值显示未知 |
| 下一步/决策 | 下一问题、理由、所需输入、用户的取舍 | 留在原会话，支持继续、改方向或停止 |

文件一经生成即可看，不等总任务完成。最低产物描述为 `artifact_id, kind, version, sha256, size, producer_call_id, input_refs, status, platform_ref`，用户/租户/节点归属由服务赋值。临时写入完成、校验通过后才原子登记；部分产物标记 partial。输出路径不能由模型指向共享任意位置。

因子/策略/回测必须复用各自已有权威存储，研究侧只登记来源关系、版本与文件清单，避免再造一套因子库和回测库。平台对象保存 `research_ref`，研究成果保存 `platform_ref`，相互跳转定位同一对象版本。保存失败时显示“计算完成，平台登记待重试”，不能伪造可用链接或重复创建记录。

研究范围内自动保存候选、草稿和实验记录属于正常工作，不让用户每轮手工导出；成为生效策略、独立验证通过、进入模拟或交易分别有明确状态/操作。因子“已入库”仅表示可复用候选，并非已证明有效。

### 10.3 一个完整案例的验收故事（设计示例）

用户从新想法“成交量过滤是否改善动量策略”开始。Agent 读取目录，展示实际可用数据，讨论确定范围后检查数据、实现原策略和过滤候选、运行基线及对照。页面能打开它刚写出的代码和正在运行的回测。

用户在候选回测中点击“打断并发送”：改为先检查高换手月份。系统停止该子作业，显示中断证据；Agent 回复已调整，生成新的分析代码，保留旧实验为已中断。用户讨论认可后继续，Agent 根据结果决定是否再做成本压力或放弃假设。

结束时，无论结果正负，用户都能在因子库打开相关候选，在策略页面打开可执行版本，在回测页面打开真实结果，在原会话看到比较依据和下一步。上述任一环节只有文字、假链接或脱离平台的报告，均不能算案例通过。

## 11. 框架选型：使用 Deep Agents + LangGraph

### 11.1 选型依据与复用边界

2026-09-12 核查官方文档与本仓库源码后的设计决定：**使用 Deep Agents 的现成 Agent，底层采用它已有的 LangGraph；在独立研究运行环境中部署，复用 PostgreSQL、Redis/Celery 和 Docker。** 不自行实现 ReAct 循环、通用消息协议、通用文件工具、上下文压缩或图执行器。下表为能力比较和本项目判断，不表示已经完成框架运行验收。

| 方案 | 官方已有能力 | 本项目判断 |
| --- | --- | --- |
| **Deep Agents + LangGraph（选用）** | 工具驱动 Agent、任务规划、文件操作、上下文管理、沙盒后端；底层提供流式、检查点和人工介入 | 最接近本次“能写代码和做实验的研究 Agent”；只接量化工具和业务控制，不手写一个图来固定所有研究步骤 |
| AgentScope + AgentScope Runtime | ReActAgent、工具/流式结果、实时中断，Runtime 有服务化与分布式中断支持 | 可行备选，尤其适合实时打断；但本次规划、文件/编码与持久执行的组合仍需更多集成。只有主选型实测遇到明确阻塞才重开决策，不两套同时建设 |
| QwenPaw | 基于现成 Agent 生态的成品服务，提供会话 API、流式、多轮历史和停止入口 | 仓库有代理和部署文件可参考，但不是当前研究工作台主控；多用户隔离、受管量化作业和成果归属仍要补。不能因为叫 QuantBot 就认为已接回 QwenPaw |
| 只用 LangGraph 自行搭 Agent | 检查点与人工介入组件 | 比 Deep Agents 更底层；本次没有理由重新编写已由上层提供的规划/文件/上下文能力 |

本地证据：`electron/src/services/qwenpaw-client.ts` 实际调用 `/api/v1/quantbot`，`listChats()` 返回空列表，`createChat()` 返回固定 default，发送 history 为空；`scripts/run_quantbot_session.py` 是另一条真实 QwenPaw SSE 验收入口。二者不能混称同一持久会话实现。`TradingAgents-astock/pyproject.toml` 已声明 LangGraph，但其依赖范围不能代表主服务装好了新版本 Deep Agents；研究运行环境单独锁版本，避免影响现有 TradingAgents。

### 11.2 谁负责什么

| 交给现成框架 | QuantMind 只补业务集成 |
| --- | --- |
| Deep Agents 的 Agent 创建、工具循环与任务规划 | 研究问题、授权范围、平台工具注册和任务状态展示 |

| 框架消息/工具/状态 streaming | 将事件显示成活动卡；必要的可回放业务事件归档，不另造一套模型消息标准 |
| 框架人工介入与状态恢复 | 用户指令何时生效、现有外部回测/训练如何取消和重接 |
| 现成 sandbox backend 协议 | 对现有受管 Docker 作业做薄适配；宿主资源和量化数据权限由平台控制 |

首先用框架提供的构造入口和扩展点；不继承重写整套 Agent，不同时引入另一套调度框架。沙盒优先选兼容本地 Docker 的现成后端，若锁定版本无合适实现，只实现标准协议的最小 Docker 适配器，沿用平台作业管理。不能把裸 `FilesystemBackend` 或路径限制当成任意代码的安全沙盒。此边界参考[官方沙盒协议](https://reference.langchain.com/python/deepagents/sandboxes)。

使用开源库与现有基础设施自托管；本设计不依赖另购托管 Agent 服务。远程网页访问、模型配置、身份和授权通过平台服务处理。GLM 的工具调用、流式参数、上下文与中断行为要在所选版本实测，不因为支持 OpenAI 风格 URL 就宣布兼容。

### 11.3 开发前的短验证关卡

只在隔离环境锁定一组 Deep Agents/LangGraph/模型适配库版本。用真实 GLM 验证：连续多轮工具调用、读取/修改文件、执行可取消的测试作业、持续消息、停止后继续、进程重启读取检查点。再验证一个已有量化工具并产出可打开的平台候选。记录确切版本、图状态、工具 ID 和故障结果。

若框架不通过上述关卡，记录具体不兼容和最小复现再重新选型；不一边标记“框架已支持”，一边在旁边重写自研执行引擎。基础框架部分已完成隔离短验证，真实量化成果登记仍待完成，因此本关卡尚未全部关闭。

## 12. 服务内持续运行、实时控制与恢复

### 12.1 运行结构

产品发送消息到已有认证 API；API 先持久化业务命令并返回消息 ID，再唤醒独立研究 Agent worker。worker 加载该会话的 LangGraph 检查点，运行 Deep Agents，调用量化工具；长训练/回测提交给现有受管作业并返回 `job_id`。工具完成后以结果消息唤醒原会话，不让浏览器持有运行生命周期。

Agent 等实验时进入等待状态，不靠模型反复查询“好了吗”。用户此时发问，由同一会话的新处理轮读取当前实验摘要并回答。单会话同一时刻仅一个 Agent 决策写入者，重型作业可在后台继续；避免两个模型轮同时修改同一计划。框架检查点恢复负责 Agent 状态，平台作业记录负责真实进程状态，两者通过稳定工具调用 ID 关联。

模型调用和实验控制分开处理。旧 `research/tasks.py` 的模型讨论与进度共享队列，不能继续承担即时控制。复用现有 Celery 命名队列，Agent 调用不占用取消/截止处理资源；控制 API 可直接使下一次派发失效并通知所属 worker/作业管理器。短作业和读取可直接作为工具，长实验必须异步提交，避免一条模型回复等待数小时。

### 12.2 不能混淆的两种中断

LangGraph 的 `interrupt()` 是保存状态并等待用户决定的断点；恢复时所在节点可能重新执行，断点前副作用必须幂等。它不自动杀掉平台 Docker/外部回测。即时停止需要运行任务取消加对应工具的取消回调，两者都验收。依据：[官方 interrupt 语义](https://docs.langchain.com/oss/python/langgraph/interrupts)。

控制动作先落库并递增 `control_revision`，工具派发前校验会话/窗口/版本。迟到模型结果、旧 worker 和旧消息重试不能在新版本下继续派发。已经提交的作业绑定原版本，取消时按精确归属逐一停止，不按用户/进程名粗暴批量 kill。

在控制与提交竞态中，提交入口必须和版本检查在同一受管临界区；提交刚成功但回执丢失时，用幂等键找回 job_id 并执行取消。停止状态只有在确认关联作业已经终止后提交。无法确认时明确显示“停止待确认”，禁止新的执行，不显示假成功。

默认控制目标（待测试）：服务健康时 1 秒内确认消息已保存，2 秒内接受停止指令并禁止新派发；可受控子进程 10 秒内先正常终止、必要时强制终止。超过目标就显示具体未停止的作业。供应商端模型计费不在进程控制保证内，超时后迟到输出只归档不生效。

### 12.3 业务状态与消息一致性

界面主状态为讨论中、工作中、等待实验、等待你的决定、正在暂停、已暂停、正在停止、停止待确认、本窗口结束、课题完成。模型返回一轮结束不等于研究完成。研究结论单独记录“支持/反证/证据不足”，执行错误单独记录失败原因，不用一个 completed 混在一起。

扩展现有 case/window/draft 的身份和关联，不新建第二套课题系统。框架 checkpoints 保存 Agent 消息与状态；现有研究业务记录保存研究合同、窗口和控制版本。确需补充的持久记录仅为消息回执/幂等命令、工具调用与已有 job_id 的关系、产物与平台对象关系，以及 UI 回放所需事件。优先复用已存在日志和存储，实施时审计后决定迁移字段。

每条工具事件关联 `case_id, run_id, turn_id, call_id, control_revision`。回放以服务生成的单调游标读取，不按两台机器时钟排序；浏览器断线后补历史再订阅，重复事件去重。框架 checkpoint 是恢复权威，UI 事件是展示投影，不能由前端状态反向决定是否运行。参数与输出脱敏后才进入事件存储。

客户端提交使用稳定请求键；并发发送按服务接收序号处理。用户消息读取位置也进检查点，不能重启后重复应用修改。状态冲突返回当前版本和差异；一个浏览器标签不能静默覆盖另一个标签已修改的计划。

### 12.4 不超过 8 小时的运行窗口

窗口同时包含墙钟截止和计算/尝试累计账本。任务约定里给出本次时长，最长 8 小时，允许提前结束；重启、重试和等待用户不重置截止。长周期由多个有边界的窗口组成，当前未得到跨窗口周期授权就停在窗口结束，保留下一步而不自动续费或重启。

用模型实际 Token/调用记录计量；供应商不返回费用时记未知，不能填零。Flash 作为初始默认，升级模型需要在会话模型策略内，429/临时故障按 Retry-After 与有抖动退避执行；总期限内仍持续失败则等待或阻塞，不能无限高速重试。

重启后加载 checkpoint，先核对受管作业与产物：仍运行则接回，已完成则读结果，确实失败则记失败。结果已写但尚未登记的作业按幂等 ID 补登记；状态不明不盲目重投。模型请求可能重复计费，必须在账本保留未知尝试。单节点重型计算先沿用一个槽位，两方向可交错推进，不能靠新增 Agent 绕过资源限制。

独立 watchdog 检查截止、租约和进程心跳，不依赖 LLM 返回。没有新证据/材料/待执行动作时待机，避免为耗 Token 生成新课题。到期保留所有中间成果和接续说明，仅在需要决定、重要发现、完成或持续故障时提示用户。

本地和云端使用同一框架与工具合同，会话明确属于执行节点。关浏览器不停止云端作业；Mac 休眠会中断本机运行，恢复后仍按原截止核对。跨节点接续沿用 AGENTS.md 的项目共享规范，当前不迁移活动进程、租约或数据库；目标节点必须可取得完全一致的输入及代码。

接入时必须处理的已见问题：

- `services/pipeline_service.py` 推理路径调用 `mark_latest_run`、`publish_signals`；研究工具必须走无信号发布的业务路径，并核对回测实际使用生成的代码/预测。只把参数设成“研究”不算隔离证明。
- `routers/ai_ide/executor.py` 向执行环境透传数据库/服务配置；研究沙盒不能原样继承这些凭据和权限。代码通过受控工具取得数据与登记产物。
- `quantbot_router.py` 的部分因子回环走内部管理员登录，不能作为多用户研究工具的身份模型；接入真实调用者的权限校验。
- AlphaAgent 部分取消依赖进程内句柄，重启后的取消能力必须补实测；“文件恢复任务记录”不等于恢复了对旧进程的控制。
- `research/tasks.py` 里长模型调用与研究推进共享执行资源，必须分离控制职责；不单纯调高并发掩盖问题。

## 14. 编码、数据和实验的必要约束

完整编码能力在独立课题沙盒内提供：允许编辑方法/因子/策略代码、配置和测试，安装已授权来源的依赖到任务环境，运行命令和修错；每次实际实验锁定代码/环境版本。代码不需要预先存在，也不受旧模板公式语言限制。

沙盒只读挂载固定数据，独立可写目录存课题代码、派生数据和结果；不挂载 Docker socket、宿主源码可写目录或生产数据库凭据。Docker 生命周期由平台外部管理。网络访问按已授权的资料/依赖工具提供，下载代码先保存审阅和版本记录；模型看到的网页、论文或工具输出均是资料，不能修改系统权限。环境隔离由执行器强制，不能仅在提示词里写“不要访问”。

允许准备新数据，不要求所有输入事先就绪：Agent 可检查现有数据源、调用授权的数据准备/采集作业、在沙盒计算派生字段。新增商业源、凭据、共享基础数据发布或应用源码变更超出当前课题执行范围时提出明确请求；已有范围内的读取与准备无需逐次审批。

每个实验固定对象/期间/数据版本/代码/参数/费用/基准/评估用途。开发搜索与留出验证分开，反复查看过的区间不能再标新留出；尝试次数跨会话窗口累计。市场的历史成分、数据实际可得时间、复权、标签与交易延迟按现有合同检查，缺口阻止相应结论而非伪造值。

研究结论必须引用程序产出的度量与实验；Agent 可以解释和提出下一步，不能写数字替代计算。失败实验、负结果与中断记录保留，用户能看到为什么停止某个方向。文章总结、因子代码、开发回测、独立验证、向前模拟是不同成果类型；各自完成条件单独显示。

## 15. 如何验证“这次做出来有用”

下列标准全部基于真实浏览器、服务和产物；不能仅靠 mock 对话或 schema 单测宣称完成。

| 验收场景 | 必须看到的证据 |
| --- | --- |
| 从空白想法建课题 | 无现有策略 ID 也能讨论，Agent 实际查能力/数据并形成具体问题；未确认研究前无实验自动启动 |
| 从材料研究新方法 | 来源/正文、提取的方法、真实代码修改、运行和对照结果；不能只输出方法摘要 |
| Agent 根据反馈推进 | 至少一次真实工具输出影响下一动作，有关联 call_id；预排好的固定步骤不算自主调整证据 |
| 过程可见 | 工具开始、日志/真实进度、结果、错误、代码 diff 和文件均可点开；模型说明与工具事实分开 |
| 运行时普通提问 | 回测继续时消息被保存/读取，Agent 根据当时状态回答；不等重型任务结束，不错误取消实验 |
| 打断并改方向 | 对模型调用中、代码执行中、训练/回测中分别测试；实际停止后才能显示已停止；新指令改变后续动作，旧结果不触发新实验 |
| 中断后继续 | 检查点、未完成步骤与输入版本保留；中断实验不冒充完成，不整轮盲目重跑 |
| 平台成果可用 | 新因子/策略候选和回测出现在原模块；双向链接指向同一 ID/版本；能作为另一课题输入 |
| 刷新/断线 | 会话、事件、文件和状态恢复；重发消息不重复执行；关闭页面不停止远端研究 |
| 服务崩溃/回执丢失 | 重启接回同一个 job_id，补登记既有产物；模型计费不明保留 unknown，不误重启已取消任务 |
| 截止与限流 | 窗口绝不因重试延长；真实 429 或受控故障注入下退避、不忙循环；实际停止所有所属作业 |
| 权限与节点 | 他人会话/产物不可读写；模型无法越出课题沙盒；本地不写云端正式库；切换节点不串会话 |

先以短实测验证上述关键控制，再做一次数小时且 ≤8h 的隔离连续运行。单次 15 秒截止测试不能替代数小时验收；框架文档“支持持久化”不能替代进程崩溃与外部副作用的测试。

每个完整案例的最低交付包：原始输入与约定、资料/数据版本、可执行代码、实验记录和中间文件、真实平台对象链接、结论与下一步、用户介入记录。对因数据阻塞而无法回测的案例，交付已完成资料/代码/数据检查及具体缺口，不拿它替代至少一个真实实验闭环的产品验收。

研究价值展示为“已验证一个假设 / 排除一个方向 / 得到可复用因子或方法 / 改善成本或稳定性 / 找到明确数据缺口”，同时展示相对基准和风险结果。负结论也是成果，但不能用调用次数或自动生成的长报告充当价值。保留两条研究线，方法成果进入策略实验时使用明确版本引用。

## 17. 2026-09-12 Agent 产品实现与下一步

本次在 `codex/research-agent-product` 独立 worktree 实现第一条真实产品链路。引擎使用 **Deep Agents 0.7.13 + LangGraph 1.2.11**，单独 Python 3.11 服务镜像，原主服务依赖不升级。实际运行验证使用 GLM-5.3-Flash；GLM-5.3 的框架兼容证据见前次记录。部署、案例编号和限制见[产品验收记录](research-agent-product-validation-20260912.md)。

### 已实现并做短流程验收

- 主入口为持久 Agent 课题，包含问题、对象、材料、模型选择；策略链路/新因子卡片给出可编辑起点。创建只讨论，计划列出问题、方法、步骤、产物、判断标准、缺项及允许工具。
- 原生 Agent 工具选择、文件读写、Python 执行、任务清单与 PostgreSQL 检查点；JSON 业务状态仅管理身份、计划审批、窗口、消息收件箱和平台引用，不另写 ReAct。
- 同一个会话可以发普通消息、打断、打断并发送调整；消息显示收到/已读/已回复/已打断。工具名称、参数、结果、实际后台作业与日志可查看，页面每 1.5 秒刷新持久事件。
- 本版计划必须勾选后执行，允许工具与截止时间由服务强制检查。每次 0.05–8 小时、最多 1–20 个后台作业；到时撤销执行许可并停止作业，不自动再开窗口。普通消息可查询状态和文件，不能启动计算/入库。
- 代码作业是无网络、无凭据、只读根目录的 Docker 子容器，只写本课题 `/workspace`、只读 `/frozen`。耗时作业立即返回编号，Agent 可在运行期间回答问题；作业完成后在同一会话接续。
- 实际因子代码进入现有因子库，策略代码通过唯一策略存储服务进入 AI-IDE，固定模板回测经过已有独立账务核验后进入平台回测记录。候选状态、来源课题、输入快照、代码哈希和回测文件哈希保留；页面能跳转、返回来源课题。
- 材料上传（单文件 2 MB）、代码/JSON/图像预览与单文件下载（20 MB）；原文件保留在节点工作区。研究回测不会被普通历史“只保留最近 10 个”的清理逻辑删除。
- 服务重启保留对话、原生检查点、文件和成果；响应不明的模型回合先停旧工作再等待用户继续。一个课题的慢核验/错误不阻塞另一个课题的控制消息。

### 仍需迭代，不能算已交付

1. **方法研究输入扩展**：受控论文/网页检索、PDF 解析、数据准备工具与来源登记。当前可研究用户提供的正文/代码/小文件，也可在已有冻结数据上写 Python；没有通用联网研究工具。
