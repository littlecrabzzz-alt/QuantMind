# 研究输入与数据发布优先级

用途：在本地 Mac 按课题需要准备固定输入，解释优先级覆盖和独立结构化发布的运行边界。不以历史一次验收断言当前服务或数据已就绪。

| 层级 | 输入与用途 | 准入要求 |
| --- | --- | --- |
| P0 | A股日线、复权、日历、基准、选用量价因子、停复牌/涨跌停 | 来源和复权口径明确；实际区间与列/行数核对；Parquet、PG、Qlib及应用日期分别检查；固定输入有哈希清单 |
| P1 | 行业指数与历史成员、ETF、课题所需财务 | 行业信号先独立验证；成员/财报/基金持仓的生效或公告可得时间未证，不称PIT因子或可交易组合 |
| P2 | 非当前课题跨资产/远期历史、公告附件和全文 | 不作为P0/P1课题的总前置；保留原始对象、失败及采集检查点 |

采集成功、发布、缓存校验、应用读取、固定输入准入是不同步骤。总历史任务清零和全文解析完成不是开始合格量价研究的条件，但任何缺口都不能靠前向填充或“已发布”声明抹平。

## 调度配置

`config/tushare-research-priority.json` 是覆盖项，不是全量运行配置。应用时保留其余字段并合并 `group_weights`，不能直接替换私有 `pipeline-config.json`。实际进程参数和配置须另核对，仓库覆盖文件不等于已部署。

- `rrg/structured/market` 权重分别为10/10/4；快速通道每两次调度优先尝试核心API，仍受家族资格、近期/历史轮转和账号/API速率门禁约束，不是固定吞吐保证。
- 近期结构化按日核心请求可以独立于长历史游标准入；不为追近期重置历史游标，不用未完整日历删去自然日空请求。
- 正文预算为每轮最多300个处理阶段、30秒、4下载线程/1解析进程。阶段间检查预算，在途工作可能超时；处理阶段数不等于独立文档数。不删除历史和失败记录来提高表面进度。

## 结构化研究独立发布

Tushare唯一采集writer的持久化尝试/Parquet可生成研究范围发布 `RESEARCH_CURRENT.json`，与完整 `CURRENT.json` 分开。研究API集合由实现中的 `RESEARCH_APIS` 管理，缓存入口为 `scripts/tushare_research_cache.py`；扩大集合时必须同步核对实际服务的显式 `--apis`，只改默认值不会改变已运行命令。

覆盖项 `research_publish_interval_seconds=900` 启用独立发布；默认关闭，要求原完整发布间隔已大于零。900秒是成功检查后的调度间隔，不是端到端15分钟时效保证。独立发布不构建正文索引、不包含正文/完整历史manifest；`history_complete/historical_versions_complete=false` 保留其真实含义。

只有请求接口全部被研究指针覆盖时才选择该源，否则使用完整发布。子集/下载逐项验证内容哈希、大小和observation引用，失败保留已验证版本；扩大接口集合可复用较窄已验证缓存，但旧分区、文件描述与新发布必须一致，不满足时完整重验。不得用损坏旧清单授权复用。

两类发布仍共享唯一writer及 `pipeline.lock`，完整发布期间采集和研究发布会等待；分离的是正文索引依赖，不是新增并发采集器。本机发布、缓存刷新和清单/文件校验会叠加延迟，缓存受实际空间预算约束。应用读取须核对当前本地配置、挂载和已验证的数据版本。

## 固定输入与恢复

每次固定输入交付记录本地运行实例、来源release/数据日期、代码版本、实际读取列与行数、缺口及输入manifest；先验证读取，再创建课题/训练。新发布不自动替换旧课题的release，缓存回收也不能删除固定研究仍引用的文件。研究冻结和最近半年保留规则见[冻结研究合同](frozen-research-workflow.md)。

运行配置升级须先识别实际唯一采集进程与ENABLED控制，保存原配置，在当前任务自然排空的窗口应用合并配置；不得并发再开采集writer。这里只给变更约束，不授权重启或采集，安装与恢复使用[本地数据源说明](local-market-source.md)的现行入口。

停用研究独立发布时，排空后将间隔恢复为0，并保存、移开 `RESEARCH_CURRENT.json` 才回落完整源；仅关闭周期会继续提供最后研究版本。不得删除仍被该指针/固定课题引用的manifest或数据。回退代码还须检查文档claim schema兼容，不能凭恢复旧配置就认定派生索引可以降版。

这些步骤仅证明数据交付，不证明完整历史、PIT、ETF执行、独立策略验证或实盘就绪。
