# 回测成交与资金账本修正

2026-09-07：本轮修正执行边界和记账，沿用已有模型与研究区间，不调整选股参数。

## 正式回测与近似研究的边界

API 的 `use_vectorized=true` 请求目前会回退到 Qlib step 引擎，日志记录实际执行模式和原因。仅凭 TopK 类名、每日全量调仓，不能保证两种引擎等价：近似引擎没有整手约束、最低佣金、分市场过户费、成交量冲击，也不执行请求中的开盘成交规则。恢复自动路由前，必须有这些维度的对照验证。

直接调用 `VectorizedBacktestEngine` 仍可用于研究。它接收**已经按执行日期滞后**的信号，收盘时先对原持股数量估值，再卖出、按实际可用现金买入，手续费在当日扣除。持仓价格变化产生的权重漂移会体现在调仓金额中。无信号日继续持有；缺失、非正和无限报价只允许用历史有效价估值，不能成交。

报告遵循 Qlib 的资金口径：`return` 是扣费前收益率，`cost` 是费用除以前一日净值，`cost_amount` 是费用金额，`account = 上日净值 × (1 + return - cost)`；`cash + value = account`。首次建仓费用计入回撤。近似计算器的收益不再提前一天入账；夏普用日净收益均值和标准差计算。

如果提供 `$change`，缺失或无限涨跌幅会阻止当天交易；省略整个 changes 参数代表调用方没有启用涨跌停检查。该近似模式不能据此形成正式交易结论。

## CnExchange 的报价约束

`get_close` / `get_factor` 继续保留有限时间的历史估值回退。成交使用当前请求区间内、对应买卖方向的指定价格，开盘价缺失时不改用收盘价或上一日价格。当前 close、volume、factor 必须有限且为正；涨跌幅数据必须有效。无效数据会阻止成交，不会清除持仓。

历史 ST、上市初期、板块切换及精确涨跌停价格仍使用既有近似规则；长期停牌的估值回退上限也未在这轮解决。本轮没有证明所有历史市场规则均准确。

## RiskGate 批次约束

逐笔校验有限正价格和数量，对已接受的开仓订单累计预留同一股票的敞口；空头持仓按绝对市值计入。未成交的平仓、反向开仓不能提前释放容量。输入字典不再被原地修改。

显式 `SELL_TO_CLOSE` / `BUY_TO_CLOSE` 不受持仓集中度限制，也不会因开仓换手预算而被同比缩减；仍受单笔金额、价格偏离约束。平仓换手会占用剩余开仓预算。缺少有效账户资产或回撤数据时阻止开仓。兼容旧信号，但只有显式平仓动作可享受减仓豁免。

**这不是完整下单风控。** 调用方仍需核验可平仓数量、可用资金、跨批次挂单和成交状态。当前静态检索仅找到 runner 的兼容包装与测试调用，生产订单使用另一个 RiskService；本轮未把新闸门接入真实下单链路。

## 验证与保留产物

在固定 OSS 镜像的独立测试容器中，用同一套用例检查旧版本 `3c45a6f` 和修正版：旧版 59 失败 / 24 通过；修正版 83 通过。覆盖日期错位、持股漂移、费用现金恒等式、停牌与无效报价、方向限制、批次敞口和减仓优先。

复用 `results/frozen-controls-20260907-v3/` 已冻结的 100 股票池、5700 条模型/对照信号及行情，以本轮 CnExchange 重放 57 个交易日。三组净收益、成交笔数与旧版本一致；模型 524 笔、单因子 384 笔、全池等权 1589 笔，逐笔现金及每日资产核对误差均为 0。这说明该样本没有因更严格的检查改变成交；异常输入由独立回归用例验证。

新产物位于 `results/execution-accounting-20260907/`：旧代码副本、失败与通过日志、JUnit XML、执行代码快照及校验清单、重放脚本、三组净值/持仓/成交 CSV。重放容器关闭网络，行情、原信号和执行代码只读挂载；所有旧测试与新产物保留。它是执行规则回归，未重训模型、未重复验证因子原始时点正确性、未做实盘验收或远程部署。

下一轮优先核对平台 RiskAnalyzer 与独立研究报告的净收益、首日费用、夏普和基准起点口径，再处理历史交易状态数据和真实下单链路的批次容量预留。
