## 需要单独登记的缺口

### 期货日历旧文档失效，不应照总览新建请求

[doc134](https://tushare.pro/document/2?doc_id=134) 正文指向 [doc137](https://tushare.pro/document/2?doc_id=137)，目前该页为 HTTP 200，但正文是 `404, 文档不存在！`。总览把它列作 `trade_cal`；当前有完整契约的 [doc467](https://tushare.pro/document/2?doc_id=467) 则叫 `fut_trade_cal`，列出 exchange/start_date/end_date/is_open 及隐藏 pretrade_date，2000 积分。两者的服务等价性不能由标题推定。

总览包含 GFEX/.GFE，doc467 参数列表当前未列 GFEX。保留交易所发现缺口，实际输入范围交给已授权样本验证；不要因此从合约 universe 删除广期所。总览提及历史开始时间也只是文档声明，不能证明每交易所从该日期完整。

### Tick 需要文件接收流程，不是采集 API 重试

[doc314](https://tushare.pro/document/2?doc_id=314) 描述约十年历史、按交易所/日期定制及每日增量的 CSV 交付。它没有固定历史起始日期、下载 URL、API 参数、分页上限或当前账户权益证明。因此 `api_names` 与 HTTP acquisition 名可保持空值，但必须用 `external_delivery` 状态解释，并单列未取得原始文件。

若后续选择购买，应先确定交付目录清单、交易所/合约/日期范围与增量交付安排，再沿既有不可变对象/manifest 协议接收文件。本批不购买、不联系供应商、不建设下载器。字段身份至少需明确交易所与原始 InstrumentID、TradingDay、毫秒 UpdateTime，以及同毫秒多条记录的保留方式；不能仅以合约+时间去重。表中的时间是否自然日、夜盘如何归交易日仍需交付样本解释。

### 指数总览里的未链接名称和代码示例

[doc93](https://tushare.pro/document/2?doc_id=93) 明确提到 `index_member`，却未给其专属链接、参数表或权限。当前台账已有 `index_member_all`，也有行业成员和指数权重接口，但名字相近不证明等价。建议父任务追加 `unlinked_api_mention` 发现项，等官方独立契约恢复或供应商确认；本轮没有证据可将它计入新增可用 HTTP API。

该页指出后缀属于编制机构/数据源且代码规律有例外。用于指导保留 supplier 原始标识，不能用示例强制重写已有 source code。名称规范说明也不等于 RRG 所需历史行业版本/公布日期证明。
