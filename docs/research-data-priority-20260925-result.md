1. 核心行情原先排在数千条股票名称变更任务后面。现在每次规划直接准入所选核心 API 最近七天的请求，上限 42 个，不重置历史游标。实际已完成 9/21–9/24 的六接口采集。
2. 文档失败重试原先对数百万条尝试记录逐文档全表计数。claim schema 7 增加覆盖索引，实库升级耗时 22.5 秒，单文档计数实测 0.214 毫秒。升级没有改写尝试历史。新配置首轮正文约 30 秒，后续一轮处理 300 个阶段，采集轮次实测约 107–123 秒。
3. 云端 QuantDB 原始行情到 9/23，但 PG 和 Qlib 停在 9/18。通过现有带锁入口重建并完整校验 Qlib；PG 按既有幂等 upsert 补入 9/21–9/23 共 16700 行，无失败批次。市场分析也验证为 9/23。
4. CLI/Celery 部分入口原先把派生失败显示为完成。现在复用统一错误判断，将失败阶段记录为 `partial`，CLI 返回非零，Redis 任务标为失败；实际选用的 API 与行情 worker 已重启加载。
5. 固定输入准备新增 `--data-root`，源码与 Mac 沙盒数据可明确分开，避免从旧主目录误取数据。

## 仍然成立的限制

- Qlib 构建报告 131 个标的没有除权事件表，另有少量事件缺行。相关标的的复权因子采用回退口径；需在确定研究股票池时检查，不能把日期追平视为全股票池执行质量通过。
- 历史 ST/涨跌停规则、行业历史成分生效时间、财务公告可得时间仍需按研究方案核验；新增缓存不会自动把这些约束接进既有策略。
- 全量 Tushare 发布仍与正文索引绑定：本次需要重建 4096 个状态桶，发布已耗时超过 17 分钟。后续应分离研究结构化数据的发布节奏与全文状态清单；本次没有通过跳过一致性校验强行发布。
- Mac 的 Tushare 休眠可用性、全历史进度，以及本地 QuantDB 应用过程中较长的停机窗口仍是运维限制；不能再让其成为固定输入研究的前置条件。
- 行业与 ETF 的正式组合回测、财务 PIT 因子和分钟/Tick 数据没有在本次宣布就绪。
