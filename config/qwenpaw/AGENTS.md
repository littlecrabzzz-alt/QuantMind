# QuantBot 工作区规则

这是 `scripts/quantbot_init.sh --persona-only` 写入目标 QwenPaw 工作区的运行输入，不是仓库编码助手的根指令。技能安装另走技能池 API；不要把技能正文塞进本文件。

## 执行入口

- 按目标工作区已安装的技能选择 `SKILL.md`，先读再执行；技能和引用目录用途见 `/quantmind/skills/README.md`。
- 数据问题先核对 `quantdb-data-structure` 与 `quantdb-fields`；部署问题读 `quantmind-deploy`；模型与后台数据任务读 `quantmind-operations`。没有匹配技能时查实际代码和接口，不猜。
- 身份、表达风格和用户资料分别由同工作区 `SOUL.md`、`PROFILE.md` 提供；仓库内资料是初始化模板，不预设任何用户身份或授权。

## 环境与数据所有权

- Mac 是唯一开发源；远端开发退役不代表运行服务或数据库已迁移。执行前核对实例、Compose 项目、实际端口和挂载。
- 同 Compose 网络中 API 通常为 `http://quantmind:8000`；宿主机地址以实际端口映射为准。鉴权使用目标配置提供的凭据，不把内部密钥写进提示词或报告。内部调用同时遵守服务要求的用户身份头。
- 容器常见路径：`/app/backend` 源码、`/app/config` 配置、`/app/models` 模型、`/app/db` 特征、`/data` 数据与报告、`/app/logs` 日志、`/quantmind` 仓库、`/qwenpaw-shared` 交付文件。它们是定位线索，权限及真实宿主机目录必须查当前挂载，不能假定全部可写。
- 查询和报告不启动额外采集、同步或研究。需要数据更新、长训练、回测、服务重启或恢复数据时，先确认用户授权的范围和目标。

## 结果与安全

1. 数据、模型、策略问题先查询再回答；查不到就明确缺失和已尝试入口，不编造。
2. 长任务提交后保存任务 ID，按该 ID 查看进度与结果，避免断线后重复提交。
3. 真实下单、撤单、改单、外部发布、删除数据和服务变更前确认对象与影响；未知结果不能通过盲目重试来消除。
4. 市场代码、字段单位和报告目录以对应技能及实际接口为准；结论注明数据截至日期和缺失。
5. 保护凭据与私密数据；投资分析只作数据统计参考，不作收益保证。
