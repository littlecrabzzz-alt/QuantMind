# 双端开发主题记录

按主题保存方案、进展和换端说明；复用现有文档、Git、Syncthing 与 `scripts/dual-node.sh handoff`，不再建立一套任务或状态系统。

```text
coordination/
  README.md
  dual-node-development/
    <UTC时间>-<节点>-<任务标识>-<随机后缀>.md
  <其他主题>/
    ...
```

## 从任何 worktree 找到同一份记录

在当前开发目录执行：

```bash
shared=$(dirname "$(git rev-parse --path-format=absolute --git-common-dir)")
# 阅读 "$shared/AGENTS.md" 和 "$shared/coordination/README.md"
# 主题记录统一读写 "$shared/coordination/<主题>/"。
```

`git common dir` 的父目录是本机主工作树。worktree 中可能有旧版 `coordination/`，不要把进展写到那个副本；已有 worktree 缺少新规则时，接续任务先读共享主工作树的 AGENTS。正在运行的任务不会自动收到新指令。

目前 Syncthing 只同步 QuantMind 主工作树，包含这里的未提交记录；独立 worktree 位于同步范围外，`.git` 也被排除。**worktree 不会自动双向同步。** 跨端接续代码仍需提交后 push/fetch 或显式传递 Git bundle，在目标端独立 worktree 检出。不要复制 worktree 的 `.git` 路径文件或把整个 worktree 加入同步。

## 更新与分工

- 开始任务先查找已有主题，读现有方案、决定和相关执行者的最新记录；已有设计文档直接链接，不复制一份新方案。
- 每次开始、方案变化、完成重要阶段、阻塞、换端或结束时追加一条短记录。微小步骤不单独记，完整日志和大产物仅写所在机器及路径。
- 每条记录新建独立文件：UTC 时间 + 节点（mac/cloud）+ 任务标识 + 随机后缀。不争写 `CURRENT.md`、全局状态表或同一条记录；修改结论时新增记录并引用被更正记录。
- 一个主题可以并行，但每个执行者先声明负责的子任务和具体写入文件，使用各自的 worktree/分支。同一文件有重叠时先协调归属，再编辑；主题名相同不代表获得整片目录的写入权。
- 联网时等记录同步并复查对方分工；离线只继续已有分工内的内容或做独立方案/实验。记录是协作约定，不是分布式锁，不能保证并发编辑代码永远没有 Git 合并冲突。发现重叠或 `.sync-conflict-*` 就暂停重叠部分，保留双方内容并协调。
- 换端记录必须给出接续的提交/补丁、输入快照、未完成项和下一步。目标端先确认这些输入确实可取得，再用新的任务标识接续并引用上条记录；不能仅按跨机器时间戳判断哪个方案生效。
- 集成时只提交已完成的明确记录文件，保留其他任务的未提交代码。源码/Git 的双端核对继续使用主工作树已有 `handoff` 入口。记录可双向同步，不改变“云端正式数据、Mac 固定快照、本地结果不自动回灌”的规则。

## 每条记录的最小模板

```markdown
# 主题：本次进展或方案
- 时间、节点、任务标识：
- 状态：进行中 / 阻塞 / 待交接 / 完成
- 分支、worktree、提交（有未提交修改须注明）：
- 分工：本次负责哪些文件；谁负责相邻工作：
- 接续/更正哪条记录：

本次完成或方案变化：只写增量，链接已有方案。
验证：命令、结果及未验证项；数据快照/产物路径，不涉及则注明。
下一步：阻塞、待办，以及接手者从哪里继续。
```

保持短小，不为凑模板补写无用内容；明确事实、提议和未验证项。
