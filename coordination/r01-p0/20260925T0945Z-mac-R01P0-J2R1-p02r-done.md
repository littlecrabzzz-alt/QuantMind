## 交付（backend/services/simulation/virtual_run/ 新目录 + 调度接入）

1. **R1 交易日流水线**（pipeline.py，stage 链 data_check→freeze_input→signal→
   risk_check→execute→settle→report）：数据就绪（消费 p02 `evaluate_data_readiness`+
   真实注册表，DailyIncrementProvider；v2 基线+全部已发布日增量合并为账本输入视图）→
   冻结身份五元组 → 月末/首日规则信号+每日风险审查 → 目标与不交易原因 →
   约定时点（次一交易日执行窗口）虚拟执行 → ReplayLedgerCheckpoint 落库 →
   run_status 直写+independent_recompute 对账。收盘信号→次日执行由账本
   LedgerOrderingError 强制+四元组证据（signal/order_decision/execution/price_mode）。
2. **R2 月度调仓+每日审查**：信号仅月末（日历最后一交易日）与冻结配置首日建仓；
   其余日 today_decision=no_trade+no_trade_reason，心跳/last_success 正常——
   无订单也是有证据的有效运行；不逐日择时（价格波动不触发订单，单测断言）。
3. **R3 幂等/锁/恢复**：阶段幂等键 `{run}:{date}:{stage}`（状态记录即凭据）；
   Redis SET NX+TTL 日锁（双 worker 让出/崩溃 TTL 接管/token 释放）；
   7 个崩溃注入点恢复==连续运行（终态指纹逐字节一致）；结果不明
   （阶段标记与账本检查点矛盾）显式 NeedsManualReview 不自动重跑；
   休眠唤醒补"无决策估值日"（不补写决策、不回填交易）；错过窗口按
   missed_window_policy（默认 skip_and_record）事前冻结策略处理。
4. **停止/恢复三段**（requested→received→effective，安全点生效：当日 settle 后/
   新决策日前）；风险暂停买入腿由账本 risk_paused 拒单、卖出仍执行、
   confirm_risk_events 逐线确认恢复（反弹不自动恢复）。
5. **无内置默认调度**：`engine/tasks/r01_virtual_run_scheduler.py` 复用
   market_sync_scheduler 模式（Redis `quantmind:r01:vr:schedule:{run}`，
   enabled 默认 False；未配置=no-op=pending_activation）；celery 任务包装在
   celery_tasks.py 新增段；beat 条目 `r01-virtual-run-dispatch`（*/5 分钟）。
6. **p03 L3 载体消费**：`virtual_run_config_from_pg_row()`（r01_virtual_run_config →
   冻结配置；主键与派生身份漂移拒绝）+ `list_enabled_pg_run_configs()`。
