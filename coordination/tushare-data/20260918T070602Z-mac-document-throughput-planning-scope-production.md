- 生产代码：`3d55da9b perf(tushare): raise bounded document throughput`，已推送 `origin/master`。代码将队列规划指纹缩小到会影响结构化任务集的配置；仅文档并发、大小限制、恢复参数变更不再触发 `configuration_changed` 规划周期。旧整份配置指纹会原子迁移到 v2，不丢规划成功时间。

## 验证

- 定向测试 51 项通过；文档发现/处理测试 90 项通过；规划、发布与 archive worker 测试 35 项通过，并在生产 Python 3.12 重复通过 35 项。`ruff`、`py_compile` 和 `git diff --check` 通过。

## 生产灰度

- 部署在一个自然周期边界停机，精确保存/恢复 `ENABLED` 标记后由安装器激活。运行时与仓库 `scripts/tushare_archive_worker.py` SHA-256 同为 `89afe39578e548d29824085d46fb2d1b1baf631965979363e711619a6bf4cc27`。LaunchAgent `com.quantmind.tushare-archive` 保持运行。
- 首个新代码周期以 4 worker 真实请求 549 次，旧指纹直接迁移，没有因部署进入 `planning_only`。
- 4 worker 基线约为每轮 80 份下载、146 个文档阶段。6 worker 三个连续周期分别完成 120/168/144 份下载和 225/313/270 个阶段，平均 144 份下载、269 个阶段。
- 8 worker 三个周期分别完成 128/93/128 份下载和 232/158/225 个阶段，平均约 116 份下载、205 个阶段；慢来源长尾使结果劣于 6，因此已原子回退到 6。
- 回退后恰逢 900 秒固定队列规划到期，该轮 `planning_only` 原因是 `interval_due`，同轮仍真实完成 269 个文档阶段。这是生产任务队列扩展，不是 dry-run 或模拟采集。
- 紧随其后的一轮于北京时间 15:05:19 完成：真实 Tushare 请求 591 次，结构化队列 pending `2,896,158`、done `326,280`，失败阶段为空；规划原因为 `interval_not_due`，未执行规划。6 worker 同时完成 168 份下载和 145 份解析，共 313 个文档阶段。
