# RRG ETF 缺价诊断批次候选

- 基线：`2994e5226e1de4bd4e1be5ac47d49b2f40bde844`，Mac 独立 worktree；没有读取凭据、调用上游、入队、发布或修改生产数据。
- 固定输入：`data-20726c7b5acbe5d15183906bba8e224d58535965f08efb0363fc296fedb51e00`；离线报告 SHA256 `3e8d713d41999897d43843263960363fe281b737a3278953b9ab5c5399802df4`。
- 只读权威队列短查询：`etf_limit` history 为 done 1 / empty 325 / pending 179 / split_pending 64；`fund_daily` 为 done 2,292 / empty 275 / pending 7,777，其中带 `ts_code` 的定向诊断任务为 0。查询使用 `jobs_partition_lookup(epoch, api_name)`，单项耗时不超过 0.13 秒。

固定版仍有 232 只 ETF、4,887 个生命周期交易日缺少 `fund_daily`，压缩为 1,888 个代码/起止日诊断范围。所有已有日线代码日都有正 `fund_adj`，不另补复权。缺价可能是停牌、生命周期边界或源端遗漏；诊断返回 0 行仍保持未分类，不能补价或标成停牌。

本候选增加 `--price-diagnostics-only`，可从同一哈希固定的审计计划生成只含 1,888 个 `fund_daily` 任务的 8 个分片；执行器只增加该 API 及其既有 `rrg` 分组。真实离线生成的分片为 1,473,421 字节，整目录 1,483,245 字节；plan-only 校验 1,888 个任务通过，0 authority、0 凭据、0 网络。

按最近 1,384 次精确请求 / 182.701 秒的实测吞吐，1,888 次约 249 秒；每次最多 360 请求，需 6 个有界执行批次。再按最近固定发布 193.257 秒计算，云端主动采集加一次发布约 7.4 分钟，Mac 镜像仍按 900 秒轮询另计。1,718 个同类逐代码 `fund_div` 回执实际新增 observation/object/parquet 共约 3.54 MB；据此本批预计约 4 MB，保守计入小 Parquet 和 manifest 增量为 4–20 MB。审计时云端可用 156,386,623,488 字节，仍满足 100 GiB 停采线。

非阻塞卡点：`fund_daily` 只能确认源端重取结果，不能权威解释可交易性；`ci_index_member` 重拉不会生成 `known_at`；5,774 个 PCF 任务继续等待独立于回测结果的历史 ETF 行业映射及盘前可知时间；全量队列和固定清单继续增长，发布与镜像耗时不能由本批外推。
