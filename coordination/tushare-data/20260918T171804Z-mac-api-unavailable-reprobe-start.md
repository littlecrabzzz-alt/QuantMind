# Tushare 已文档化但供应商当前不可用接口低频复查开始

- 时间、节点：2026-09-18T17:18Z，Mac 全量归档唯一写入者。
- 状态：进行中。
- 分工：仅修改 Tushare intake/pipeline、固定覆盖审计、对应测试与 Mac 数据源说明；生产归档继续由现有安装副本运行，候选测试不写权威数据。
- 接续：`20260918T171221Z-mac-sqlite-wal-full-production.md`。

发现：固定发布中 11 个已规划接口尚无数据，真实原始响应均为供应商业务码 40101“请指定正确的接口名”。其中 `fund_sales_ratio`、`tmt_twincome` 等仍在 Tushare 官方文档公开，不能永久当作不存在。现有七天低频复查只覆盖 `permission_denied`，这些任务在四次重试后停留于 `blocked/api_error`，若供应商恢复接口将不会自动补采。

目标：识别并保留该供应商证据，为每个 API/src 建立明确的 `api_unavailable` 能力状态；每七天以有界代表任务低频复查，成功时恢复同范围被阻塞任务；不扩大频率、不删除旧结果/attempt、不把供应商不可用伪装成权限拒绝或完成。候选在独立 worktree 开发并完整验证后再合入、部署和真实验收。
