# 已配置实例的最小联通检查

用途：发布或排障时区分服务未启动、依赖不可用、网关转发失败。以下是人工检查入口，不表示本仓库当前实例已通过。

前提：已确认目标实例、数据库、Redis、端口映射和认证配置。不要为检查而初始化新库、播种账号、重启服务或把另一个实例的数据挂过来。

## 只读检查

在端口确实映射到目标实例时：

```bash
curl -i http://127.0.0.1:8000/health
curl -i http://127.0.0.1:8001/health
curl -i http://127.0.0.1:8002/health
curl -i http://127.0.0.1:8003/health
```

分别核对服务身份、依赖状态和响应内容；HTTP 200 不等于数据库、行情或业务能力全部可用。任何 `degraded` 项都要说明原因与影响，不能直接算通过。

在已配置应用容器内，可只读检查数据库连通性、Redis 持久化和磁盘余量：

```bash
python -I -S /app/scripts/check_storage_readiness.py
```

网关链路用当前登录账号读取其本人的列表，核对 `401/403` 与代理 `502/503/504` 的区别；不要通过不存在的 URL 返回 `404` 推断内部密钥已经验证成功。

WebSocket 连接、心跳与订阅格式见 [ws_core 协议](../services/stream/ws_core/README.md)。无新行情时没有推送不能单独判定订阅失败。

## 业务检查边界

回测提交、策略激活、训练、推理、交易和数据更新会写状态或产生费用，必须作为单独授权的业务验证，不属于此只读清单。排障日志需记录目标实例、时间、接口与请求 ID，去除 token、密钥和敏感账户信息。
